## 摘要
自动化红队测试通常重复使用一组固定提示，这只能衡量已知风险，却无法从测试中发现的失败中学习。我们提出 CART（Closed-Loop Adaptive Red Teaming，闭环自适应红队测试），一个利用每次测试结果来指导后续测试内容的框架。CART 从广泛的风险覆盖开始，追踪新出现的弱点，保持新探测样本的多样性，并记录每项发现的证据和来源。它将创建测试的 Challenger（挑战者）、被测试的 Target（目标，可能是纯文本模型或受限的工具使用智能体）以及评估结果的 Judge（裁判）分离开来，使这些角色能够被独立研究。在三个评估系列（Frontier、JAH 和 Agentic）上，对于每个有可用基线的目标，CART 相比静态种子重放发现了更多失败和更高的平均风险。这些收益还扩展到工具中介的智能体测试，表明上下文自适应能够揭示直接提示重放无法触发的弱点。这些结果描述的是测试策略所发现的内容，而非失败在实际部署中发生的频率。我们还发现，Challenger-Judge 的选择会影响所发现的证据，凸显了角色分离和独立审查的必要性。总体而言，CART 将红队测试从一次性清单转变为对模型和智能体弱点的持续、自适应且可审计的搜索。

## Abstract
Automated red teaming often replays a fixed set of prompts, which measures known risks but cannot learn from failures found during testing. We present CART (Closed-Loop Adaptive Red Teaming), a framework that uses each result to guide what it tests next. CART begins with broad risk coverage, follows weaknesses that emerge, keeps new probes diverse, and records the evidence and source of every finding. It separates the Challenger that creates tests, the Target being tested, which may be a text-only model or a bounded tool-using agent, and the Judge that evaluates the results, allowing these roles to be studied independently. Across three evaluation families (Frontier, JAH, and Agentic), CART discovers more failures and higher average risk than static seed replay for every Target with an available baseline. The gains extend to tool-mediated agent tests, suggesting that contextual adaptation can reveal weaknesses that direct prompt replay does not exercise. These results describe what the test policies discover, not how often failures occur in real deployments. We also find that Challenger-Judge choices affect the evidence uncovered, highlighting the need for role separation and independent review. Overall, CART turns red teaming from a one-time checklist into a continuous, adaptive, and auditable search for model and agent weaknesses.

## 2. 论文提出的方法论

### 核心思想

- **闭环自适应**：利用每一轮测试结果更新记忆，指导后续测试内容，在“覆盖未充分测试风险”与“追踪已发现弱点”之间取得平衡。
- **角色分离**：将测试系统拆分为三个独立角色：
  - **Challenger（挑战者）**：生成测试探针；
  - **Target（目标）**：被测试的模型或受限工具使用智能体；
  - **Judge（裁判）**：评估响应或工具行动轨迹。
- **证据链完整**：记录每个探针的 prompt、响应/行动轨迹、裁判判断、风险分数及来源谱系。

### 关键技术细节

- **问题形式化**：
  - 配置包括风险类别集合 \(R\)、能力类别集合 \(C\)、攻击策略集合 \(S\)、预算 \(N\)、种子接地调度参数 \(\tau_{seed},\phi_{seed}\)、弱点追踪概率 \(p_{weak}\)、评分权重向量 \(\lambda\) 以及优先级阈值向量 \(\kappa\)。

- **单轮七步流程**：
  1. 读取过去结果，形成类别级测试计数、失败数、分数和最近证据；
  2. 策略管理器选择风险类别 \(r\) 和策略 \(s\)；
  3. 若启用种子检索，从种子库选择一个相关案例；
  4. Challenger 根据目标画像、类别、策略、历史结果、多样性要求和可选种子生成结构化测试提示及期望安全行为；
  5. Target 回答提示或完成一次有界工具使用情节；
  6. Judge 判断是否失败，并返回严重性、影响范围、可复现性、置信度、证据和建议的后续测试；
  7. 计算风险分数和优先级，保存完整记录并更新记忆。

- **弱点画像与自适应选择**：
  - 类别 \(r\) 的弱点画像 \(w_t(r)\) 为该类别历史记录的平均风险分数（未测试类别为 0）。
  - 使用 **Thompson 采样** 选择风险类别：
    \[
    \theta_r \sim \text{Beta}(f_r+1,\,(n_r-f_r)+1),\quad r^\star=\arg\max_{r\in R}\theta_r
    \]
    其中 \(n_r\) 为测试次数，\(f_r\) 为失败次数。该机制天然平衡探索与利用。
  - 策略调度包括四类分支：周期性接地检索、初始侦察扫描、弱点追踪（以概率 \(p_{weak}\)）、回退随机策略。

- **多样性控制**：
  - 策略管理器决定“在哪里测”（类别与策略），多样性规则决定“如何表达测试”（变化角色、领域、语言、格式、权威来源、交互长度等）。
  - Challenger 必须变化多个维度并记录变化内容，避免对同一弱点的近似重复探测。

- **种子谱系**：
  - 每个记录标注其来源类型：`SEED REPLAY`（静态基线直接提交）、`SEED ADAPTATION`（接地检索策略下使用种子）、`SEED EXPANSION`（其他自适应策略使用种子）、`SELF-GENERATED`（无种子）。

- **风险评分与优先级**：
  - 加权风险分数：
    \[
    \text{risk score} = \lambda_{sev}\cdot severity + \lambda_{blast}\cdot blast\_radius + \lambda_{repr}\cdot reproducibility + \lambda_{conf}\cdot (R_{max}\cdot confidence)
    \]
    非失败记录风险分数为 0。
  - 根据阈值 \(\kappa_0>\kappa_1>\kappa_2\) 将发现分为 P0–P3 优先级。

- **智能体测试扩展**：
  - Target 可为有界 ReAct 循环智能体，使用模拟工具（文件、网络、邮件、键值存储、shell、数据库、HTTP），不接触真实系统。
  - 通过确定性 canary 检测危险动作与间接提示注入。
