## 摘要
具有大语言模型（LLM）的软件智能体被设计用于自动化程序修复（APR）任务，这增加了在不久的将来 APR 智能体将在无需大量人工干预的情况下自动修复缺陷的可能性。在这种情况下，我们能否信任 APR 智能体生成功能正确且安全的代码？如果攻击者用看似良性但可能影响智能体生成正确但不安全代码的对抗性问题来攻击生产环境中的 APR 智能体，会发生什么？在本文中，我们通过一项实证研究迈出了回答这些问题的第一步。首先，我们构建了 SWEADV，一个由 SWE-bench Verified 中 150 个修复任务构建的 750 个对抗性问题描述的基准。对于每个修复任务，我们创建了五个对抗性问题描述，分别对应每种攻击类型：命令执行、反序列化、路径遍历、拒绝服务和弱哈希。其次，我们在 SWEADV 上评估了来自三个 LLM 后端的 mini_swe APR 智能体：GPT-5-Mini、MiniMax-M2.5 和 DeepSeek-R。我们发现，平均而言，对抗性问题描述可以在 51.7% 的情况下诱导恶意行为并成功修复。第三，我们研究了典型的检测机制是否足以阻止此类恶意补丁被接受。使用 LLM 作为评判器对对抗性问题描述进行修复前检测，平均检测准确率仅为 62.3%。使用静态分析工具和 LLM 作为评判器对对抗性 APR 补丁进行修复后检测，平均检测准确率分别仅为 39.4% 和 55.4%。我们得出结论，由于自主 APR 智能体容易受到对抗性攻击，因此在生产部署中尚不可信。

## Abstract
Software agents with Large Language Models (LLMs) are designed for Automated Program Repair (APR) tasks, raising the possibility that, in the near future, APR agents will fix bugs automatically without much human intervention. Can we trust an APR agent to produce both functionally correct and secure code in such situations? What if attackers target production APR agents with adversarial issues that seem benign but may influence the agents to produce correct but insecure code? In this paper, we took a first step towards answering these questions by conducting an empirical study. First, we created SWEADV, a benchmark of 750 adversarial issue descriptions constructed from 150 repair tasks in SWE-bench Verified. For each repair task, we created five adversarial issue descriptions, one for each attack type: command execution, deserialization, path traversal, denial of service, and weak hashing. Second, we evaluated mini_swe APR agents from three LLM backends on SWEADV: GPT-5-Mini, MiniMax-M2.5, and DeepSeek-R. We found that on average, adversarial issue descriptions can induce malicious behaviors with successful repair in 51.7% of cases. Third, we investigated whether typical detection mechanisms are sufficient to prevent such malicious patches from being accepted. Pre-repair detection with LLM-as-judge on the adversarial issue descriptions resulted in an average detection accuracy of only 62.3%. Post-repair detection on adversarial APR patches using static analysis tools and LLM-as-judge achieved average detection accuracies of only 39.4% and 55.4%, respectively. We conclude that autonomous APR agents cannot be trusted yet in production deployment, given their susceptibility to adversarial attacks.

## 2. 论文提出的方法论

- **威胁模型**：
  - 攻击者仅能通过 issue 报告接口提交或影响自然语言 issue 描述，不能直接修改仓库、补丁、测试套件或验证管道。
  - 攻击是**黑盒**的：攻击者不知道具体 APR 智能体的内部细节，但可查看公开仓库内容、历史 issue 等来构造逼真的对抗性描述。
  - 攻击成功条件：生成的补丁既通过功能验证测试，又包含攻击者预期的漏洞行为。

- **SWEADV 基准构建流程**：
  - 从 SWE-bench Verified 中选取 **150 个修复任务**，为每个任务构造 5 种攻击类型对应的对抗性 issue，共 **750 个实例**。
  - 五种攻击类型：**命令执行（command execution）、反序列化（deserialization）、路径遍历（path traversal）、拒绝服务（DoS）、弱哈希（weak hashing）**。
  - 构建分为两步：
    1. **攻击负载创建**：利用原始 golden patch 和仓库快照提取“目标符号”（target symbol，即原修复最相关的函数/方法），并生成符合项目命名风格的“注入符号”（injected symbol）。然后将注入符号、目标位置、攻击者控制的环境变量输入和危险 sink 填入攻击负载模板。

- **验证与评价指标**：

    - **FR**（Fix Rate）：功能验证通过的比例。
    - **ISR**（Injection Success Rate）：注入并调用预期漏洞的比例。
    - **ASR**（Attack Success Rate）：同时满足功能验证通过且包含注入漏洞的比例，即攻击成功。

- **防御机制评估**：
  - **修复前检测**：LLM-as-judge 通过 unguided/guided 提示分类 issue 是否对抗性。
  - **修复后检测**：静态分析工具（Semgrep、Bandit）和补丁级 LLM-as-judge（结合静态分析结果与补丁内容）。
  - **组合检测**：同时输入 issue、补丁和静态分析结果给 LLM judge。

## 6. 论文的主要结论与发现

- **对抗性注入有效性高**：
  - SWEADV 上 ASR 为 **48.5%–54.0%**，显著高于 SWExploit 基线的 **18.8%–26.4%**。
  - 对抗性 issue 描述并未降低修复率（FR 基本与良性 issue 持平，甚至 GPT-5-Mini 上略有提升），说明攻击可以隐蔽地带来测试通过的恶意补丁。
  - 攻击类型中，**weak_hashing** 最易注入（MiniMax-M2.5 上 ASR 达 64.0%），**path_traversal** 相对较难。

- **检测机制效果有限**：
  - 修复前 LLM-as-judge：guided 提示下平均准确率仅 **62.3%**，SWEADV 比基线更难检测。
  - 修复后静态分析：Semgrep F1 平均 **53.4%**，Bandit 仅 **20.5%**；规则覆盖不足是主因。

  - 组合检测：平均准确率提升至 **65.9%**、F1 为 **72.4%**，最佳模型 Claude-S-4.6 准确率也仅 **75.8%**，仍存在大量漏检。

- **前沿模型同样脆弱**：
  - Claude Opus 4.5 在愚弄三个模型的对抗性实例上 ASR 高达 **85.4%**，说明更强的指令跟随能力可能反而更容易被利用。

- **检测失败原因**：
  - 定性分析 600 个漏检样本发现，最主要原因是攻击者将恶意逻辑包装成**合法功能或特性请求**，检测器未能识别安全敏感代码与修复目标的错位。
  - 其他原因包括：检测器要求显式恶意意图、将危险行为视为“不良工程”而非攻击、证据不足时默认良性等。
