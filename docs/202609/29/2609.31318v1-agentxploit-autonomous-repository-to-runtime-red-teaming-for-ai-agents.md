## 摘要
AI 智能体将语言模型与外部数据和工具相结合，这些工具可以修改文件、调用 API 或执行代码。当对抗性内容改变智能体的工具使用方式，或当周围软件包含路径遍历、命令注入等漏洞时，就可能出现安全故障。我们研究经授权的白盒部署前审计，审计者可以访问目标代码仓库和受控运行时，但成功攻击仍必须通过任务定义的攻击者接口实施，并由外部验证器确认。我们提出 AgentXploit，一个双角色审计系统，它将仓库级攻击路径发现与运行时利用分离开来。分析器智能体追踪攻击者控制的输入到敏感操作，并记录代码支持的候选攻击路径；利用器智能体将这些路径转化为具体攻击，并根据运行时反馈进行修正。我们还引入了 AgentXploit-Bench，其中包含 12 个开源 AI 智能体系统和框架中的 72 个可复现漏洞。在三次运行中，AgentXploit 的端到端成功率达到 59.3%，而 Codex 为 38.4%。在 token 预算匹配的比较下，Codex 达到 46.3%。在提供了注入点的 AgentDojo 上，利用器智能体的攻击成功率达到 79.2%，而 AgentVigil 为 52.7%。这些结果凸显了代码仓库发现和运行时利用是端到端智能体安全审计中两个不同的挑战。

## Abstract
AI agents combine language models with external data and tools that can modify files, call APIs, or execute code. Security failures can arise when adversarial content changes an agent's tool use or when the surrounding software contains vulnerabilities such as path traversal or command injection. We study authorized white-box pre-deployment auditing, where the auditor has access to the target repository and a controlled runtime, but successful attacks must still act through the task-defined attacker interface and be confirmed by an external verifier. We present AgentXploit, a two-role auditing system that separates repository-level attack-path discovery from runtime exploitation. The Analyzer Agent traces attacker-controlled inputs to sensitive operations and records code-supported candidate attack paths; the Exploiter Agent turns these paths into concrete attacks and revises them using runtime feedback. We also introduce AgentXploit-Bench, containing 72 reproducible vulnerabilities across 12 open-source AI-agent systems and frameworks. Across three runs, AgentXploit reaches 59.3% end-to-end success, compared with 38.4% for Codex. Under a token-budget-matched comparison, Codex reaches 46.3%. On AgentDojo, where injection points are provided, the Exploiter Agent reaches 79.2% attack success versus 52.7% for AgentVigil. These results highlight repository discovery and runtime exploitation as distinct challenges in end-to-end agent security auditing.

## 1. 论文的核心问题与整体含义

- **研究动机**：AI 智能体将 LLM 与文件修改、API 调用、代码执行等外部工具结合，带来两类安全风险：
  - 对抗性内容（如提示注入）改变智能体的工具调用行为；
  - 底层软件存在路径遍历、命令注入等传统漏洞。
- **核心问题**：现有红队方法大多假设注入点或攻击面已知，只优化攻击输入，无法回答“审计者能否仅凭代码仓库自主发现可行攻击路径并在运行时验证”这一问题。
- **整体含义**：论文研究授权白盒预部署审计：审计者可访问目标仓库和受控运行时，但攻击必须通过任务定义的攻击者接口执行，并由外部确定性验证器确认。
- **提出内容**：
  - 双角色系统 **AgentXploit**，将仓库级攻击路径发现与运行时利用分离。
  - 配套基准 **AgentXploit-Bench**，包含 72 个可复现漏洞，用于评估端到端、仅分析、仅利用三种模式。

## 2. 论文提出的方法论

- **双角色架构**：
  - **Analyzer Agent（分析器）**：
    - 搜索仓库，维护调查队列和存储在模型上下文之外的证据报告。
    - 使用目录、文本搜索、文件读取、依赖、符号、AST、LSP 等工具，追踪外部输入到敏感操作的数据流。
    - 输出机器可读候选攻击路径记录，包含：路径类型、入口点、敏感操作、代码位置、所需前置条件、可选利用提示。
    - 通过优先级队列逐步扩展证据，最终生成候选攻击路径报告。
  - **Exploiter Agent（利用器）**：
    - 读取分析器报告，构造具体攻击并通过攻击者接口执行。
    - 根据目标响应和允许的执行轨迹进行迭代修正。
    - 对实现级漏洞遵循代码代理循环；对 LLM 中介攻击选择并适配注入种子。
    - 支持多处注入点协同：在不同工作流阶段放置一致指令，早先内容建立角色或触发线索，后续内容激活同一攻击目标。
- **攻击路径分类**：
  - **直接路径**：从攻击者接口可达的入口点开始（如 API、用户查询通道）。
  - **间接路径**：从外部数据源开始（如检索文档、工具响应），被智能体后续消费。
- **成功判定**：外部确定性验证器独立检查目标状态，代理不能自行声明成功；审计访问、运行时行为和成功检查三者严格分离。

## 3. 实验设计

- **AgentXploit-Bench**：
  - 72 个可复现漏洞，来自 12 个开源 AI 智能体项目（如 GPT_Academic 22 个、OpenClaw 10 个、AgentScope 9 个、LangChain 8 个、LobeChat 8 个等）。
  - 每个任务包含固定易受攻击版本、攻击者接口、目标容器和外部确定性验证器。
  - 三种评估模式：
    - **Analysis-only**：仅评估攻击路径恢复，不执行目标。
    - **Exploit-only（oracle）**：提供漏洞规格和攻击目标，隔离利用构造能力。
    - **End-to-end**：主任务，隐藏漏洞特定元数据，需同时完成发现和利用。

  - 提供预定义注入点，隔离运行时攻击构造阶段。

  - 每次任务最多 50 次攻击迭代。
