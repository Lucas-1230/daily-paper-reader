## 摘要
评估编码智能体对网络安全漏洞的感知能力，需要能够揭示能力差距并随着模型演进仍保持信息量的评估方法。静态基准提供固定的覆盖范围和难度，而稀缺的漏洞仓库和昂贵的专家编写限制了其大规模更新。我们提出 SecProbe，一个结合项目反应理论（IRT）与按需合成仓库级漏洞修复任务的自适应评估框架。根据观测到的性能，SecProbe 估计智能体能力，并识别额外证据最具信息量的位置，相应地选择现有任务或合成新任务。作为一个用例，我们构建了 353 个任务，涵盖六种编程语言和 151 种 CWE 类型，并使用两种智能体运行框架评估了九个前沿模型。成功率最高为 28.33%，凸显了漏洞识别和修复方面的巨大差距。与随机和一次性基线相比，SecProbe 获得了可比的智能体能力估计，同时要求智能体解决的任务数量减少最多 29.5%。这些结果支持自适应评估作为一种高效且有区分度的方法来评估网络安全漏洞感知能力。

## Abstract
Assessing cybersecurity vulnerability awareness in coding agents requires evaluations that reveal capability gaps and remain informative as models evolve. Static benchmarks offer fixed coverage and difficulty, while scarce vulnerable repositories and costly expert authoring limit their renewal at scale. We introduce SecProbe, a framework for adaptive evaluation that combines Item Response Theory (IRT) with on-demand synthesis of repository-scale vulnerability-repair tasks. From observed performance, \textsc{SecProbe} estimates agent ability and identifies where additional evidence is most informative, selecting existing tasks or synthesizing new ones accordingly. As one use case, we construct 353 tasks spanning six programming languages and 151 CWE types and evaluate nine frontier models with two agent harnesses. Success rates peak at 28.33\%, highlighting substantial gaps in vulnerability recognition and repair. Compared with random and one-shot baselines, \textsc{SecProbe} achieves comparable agent ability estimates while requiring agents to solve up to 29.5\% fewer tasks. These results support adaptive evaluation as an efficient and discriminative approach to assessing cybersecurity vulnerability awareness.

## 2. 论文提出的方法论

- **核心思想**：SecProbe 将 **IRT 自适应任务选择** 与 **按需多智能体任务合成** 相结合，形成“观察—行动”闭环。
- **任务定义**：
  - 每个任务要求智能体在保持功能的前提下，定位并修复仓库中的漏洞。
  - 任务形式：\(x = (s, P_c, T_{\text{func}}, T_{\text{sec}}, m)\)，其中 \(s\) 为软件规格，\(P_c\) 为注入漏洞后的项目，\(T_{\text{func}}\) 为功能测试，\(T_{\text{sec}}\) 为安全/利用测试，\(m\) 为元数据。
  - 修复成功的判定条件：修复后功能测试通过，且安全测试全部阻止利用样本（即 \(T_{\text{func}}(P_c \oplus \Delta)=1\) 且 \(T_{\text{sec}}(P_c \oplus \Delta)=1\)）。
- **多智能体任务合成流水线**：
  - **Online Security Researcher**：检索权威资料，生成结构化安全画像 \(\phi_c = R(c)\)；
  - **Task Architect**：根据画像和规格生成仓库级任务蓝图 \(b = A(\phi_c, s)\)；
  - **Exploit Test Strategist**：设计利用样本和功能测试策略 \(q = S(b, \phi_c)\)；
  - **Repository Engineer**：构建可执行任务实例 \(x = E(b, q)\)；
  - **Security Reviewer**：独立审计并返回通过或需修改的决定 \(v = V(x)\)；
  - 最终由确定性验证器判定任务是否进入评估池，最多进行 10 轮修复。
- **难度控制**：
  - 通过超参数向量 \(h = (h_{\text{repo}}, h_{\text{arch}}, h_{\text{vuln}}, h_{\text{eval}})\) 控制代码行数/文件数/函数数、架构组件数、漏洞数量/攻击路径数、公开/隐藏测试数量和利用家族数等，实现对任务难度的细粒度调节。
- **自适应评估循环**：
  - 采用 **Bayesian 双参数 logistic IRT 模型**：
    \[
    \Pr(y_{ij}=1) = \sigma(\alpha_i(\theta_j - \beta_i))
    \]
    其中 \(\theta_j\) 为智能体能力，\(\beta_i\) 为任务难度，\(\alpha_i\) 为区分度。
  - 定义**信息缺口分数** \(G_t(\theta)\)，衡量某个能力区域是智能体池关注但现有任务信息量不足的地方：
    \[
    G_t(\theta) = \frac{w_t(\theta)}{\epsilon + \mathbb{E}_{q_t}[\sum_i \alpha_i^2 p_i(\theta)(1-p_i(\theta))]}
    \]
  - 取 \(G_t(\theta)\) 最大处为下一次合成/选择的目标难度 \(\beta^\star\)，并选择高区分度 \(\alpha^\star\)。
  - 如果现有任务池中没有合适的任务，则根据启发式映射 \(\hat\alpha_t(c,s,h), \hat\beta_t(c,s,h)\) 选择生成配置 \((c^\star,s^\star,h^\star)\) 并调用多智能体合成新任务。
  - 评估停止条件：归一化最大信息缺口低于阈值（如 0.15）。

## 6. 论文的主要结论与发现

- **前沿模型远未达到可靠的安全修复水平**：所有评估配置的严格通过率均低于 30%，最高为 GLM-5.3 + TERMINUS-2 的 28.33%；第二名 GPT-5.6-Sol 为 26.06%。
- **自适应评估显著减少所需任务数**：达到信息缺口阈值 0.30 时，自适应策略仅需 244 个任务，比随机（328）少 25.6%，比一次性（346）少 29.5%；在留出模型上，达到能力估计 RMSE ≤ 0.15 仅需 140 个任务，而随机需 181、固定顺序需 194。
- **难度控制有效**：Easy→Hard 通过率从 44.0% 降至 13.3%，平均分从 78.6 降至 55.8；仓库复杂度、漏洞复杂度和评估复杂度均能独立提高任务难度。
- **主要失败模式**：修复覆盖不完整（37.9%）、错误诊断/定位（22.9%）、遗漏应用逻辑或状态约束（20.6%）、修复引入回归（9.5%）。
