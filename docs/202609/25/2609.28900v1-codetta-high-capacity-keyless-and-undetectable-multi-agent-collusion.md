## 摘要
基于大语言模型（LLM）的多智能体系统正越来越多地部署在金融、医疗和软件工程等高风险场景中，智能体通过自然语言消息进行协调。然而，同样的信道也可能被串通的智能体用于泄露机密信息或协调未经授权的行为，而隐写术可以将此类通信隐藏在审计者阅读记录时看似正常的输出中。

现有的可证明不可检测的LLM隐写协议并不适合实际部署。高容量方案假设接收方能够复现发送方输出分布的对称场景；针对非对称智能体的最先进协议容量非常低；大多数方法依赖预共享密钥。

我们通过Codetta使不可检测的智能体共谋威胁具体化，这是一种面向实际非对称场景中独立部署智能体的高容量隐写协议。Codetta结合了用于估计通信信道的共享公共模型、保持发送方输出分布的采样机制以及自适应纠错码。它进一步通过隐写式密钥交换消除了预共享密钥，使独立部署的智能体能够建立共享密钥，同时保持记录在计算上与普通模型输出不可区分。

在三种智能体工作负载和三种发送方模型上，Codetta的容量最高达到最先进非对称协议的$94\times$倍，其密钥交换用约80k可见token建立共享密钥，经验证失败概率至多为$4.1\times 10^{-3}$。这些结果表明，独立部署的智能体之间正在实现实际不可检测的共谋，因此审计必须超越检查通信记录。

## Abstract
Multi-agent systems built on large language models (LLMs) are increasingly deployed in high-stakes settings such as finance, healthcare, and software engineering, where agents coordinate through natural-language messages. The same channels, however, let colluding agents exfiltrate confidential information or coordinate unauthorized actions, and steganography can hide such communication inside outputs that look ordinary to an auditor reading the transcript.   Existing provably undetectable LLM steganography protocols are not suited to realistic deployments. High-capacity schemes assume a symmetric setting where the receiver can reproduce the sender's output distribution, the state-of-the-art protocol for asymmetric agents has very low capacity, and most approaches rely on a pre-shared secret key.   We make the threat of undetectable agent collusion concrete with Codetta, a high-capacity steganographic protocol for independently deployed agents in realistic asymmetric settings. Codetta combines a shared public model that estimates the communication channel, a sampling mechanism that preserves the sender's output distribution, and an adaptive error-correcting code. It further removes the pre-shared key through a steganographic key exchange that lets independently deployed agents establish a shared key while keeping the transcript computationally indistinguishable from ordinary model outputs.   Across three agent workloads and three sender models, Codetta achieves up to $94\times$ the capacity of the state-of-the-art asymmetric protocol, and its key exchange establishes a shared key with about 80k visible tokens at an empirically certified failure probability of at most $4.1\times 10^{-3}$. These results show that effectively undetectable collusion is becoming feasible between independently deployed agents, so auditing must go beyond inspecting communication transcripts.

## 2. 论文提出的方法论

Codetta 由两部分组成：**带密钥的高容量隐写协议**和**无密钥的隐写式密钥交换**。

### 2.1 关键组件与核心思想

- **共享公共 draft 模型**：发送方和接收方都运行一个小型公开模型 $P_{\text{Draft}}$，仅基于公开记录估计下一 token 分布 $q_t$，作为发送方私有分布 $p_t$ 的代理。这使得接收方无需访问发送方模型或内部状态，也能估计每个 token 的熵和桶划分。
- **保持输出分布的采样机制（maximal coupling）**：发送方从目标桶中按 $p_t$ 条件采样作为提案，并以概率 $\min\{1, K_t \pi_t(a)\}$ 接受；否则从残差分布采样。该机制保证发布 token 严格服从 $p_t$，从而不改变记录分布。拒绝事件成为可纠错的替换错误。
- **自适应纠错码（alphabet-adaptive ECC）**：传统 ECC 需在生成前固定码字，但每个 token 的字母表大小 $K_t$ 在生成时才确定。Codetta 采用**在线生成校验（modular checks）**的方式：每个可用 token 携带一个模 $K_t$ 的加权校验方程，接收方通过信念传播（BP）在因子图上解码。码率随文本熵自适应，且支持非 2 的幂字母表。
- **隐写式密钥交换**：基于 **MLWE（Module Learning With Errors）**，利用 ML-KEM-512 参数将伪随机格系数作为 carrier 的均匀符号传输。载体采用 **lifted exact-cover carrier**：发送方从诚实分布抽取候选块池，通过公共哈希给每个块打标签，并用双射匹配槽位与块，使发布块始终是池中均匀样本，即使标签不平衡也保持分布不变。三阶段交换传输接收方份额 $b$、发送方向量 $w$ 和掩码预密钥 $z$；接收方通过压缩与 BCH 码纠错恢复 128 位预密钥，最后用 KDF 导出共享密钥。

### 2.2 主要算法流程

- **带密钥协议（Algorithm 2）**：  
  1. 发送方和接收方基于公开记录运行 draft 模型，得到 $q_t$；  
  2. `ChooseAlphabet` 根据熵和桶平衡条件选择 $K_t$，`Bucket` 将词表划分为近均匀的桶；  
  3. 若 $K_t > 1$，发送方根据 ECC 配置生成模 $K_t$ 校验 $C_s$，用 PRF 掩码得目标符号 $A_s$；  
  4. 发送方在目标桶中条件采样并用 maximal coupling 发布 token；  
  5. 接收方重放公开计算，读取桶符号、去掩码，累积校验方程；  
  6. 在检查点运行 BP 解码，并用 PRF 标签验证候选消息，输出消息或 $\bot$。

- **密钥交换（Algorithm 4）**：  
  1. 建立公共矩阵 $A$；接收方采样 $s_R,e_R$，发送方采样 $s_S,e_1,e_2$；  
  2. 第一阶段：接收方通过身份序列化发送 $b = A s_R + e_R$；  
  3. 发送方用 MLEW 公钥加密预密钥：$w = A^T s_S + e_1$，$z = \widehat{b}^T s_S + e_2 + \iota(c^+)$，其中 $\iota(c^+)$ 将 BCH 编码的预密钥映射到环元素；  
  4. 接收方计算 $\omega = \widehat{z} - s_R^T \widehat{w}$，舍入恢复编码位，BCH 解码得到预密钥；  
  5. 双方用 KDF 从预密钥和公开记录导出会话密钥，随后运行 Codetta 带密钥协议确认密钥一致，失败则重试。

## 3. 实验设计

- **数据集/场景**：  
  - **FINANCIAL**：合成金融情报任务，接收方提出研究请求，发送方从 20 个发行人、100 条数据库记录中检索并生成研究报告；私有上下文是检索记录。  
  - **IFEval**：来自 IFEval 数据集的指令遵循任务，发送方先在其思考轨迹中产生私有计划，再生成响应；私有上下文是该计划。  
  - **CTF**：基于 InterCode-CTF 的 picoCTF 挑战，发送方先解决挑战（工具调用、执行轨迹为私有上下文），然后撰写技术报告作为载体，通过共享文件系统传递。

- **模型**：发送方为 Qwen2.5-7B、Llama-3.1-8B、Ministral-3-8B；公共 draft 模型分别为 Qwen2.5-1.5B、Llama-3.2-1B、Ministral-3-3B。

- **对比方法**：  
  - **ARS**（BYP+25）：当前最先进的非对称隐写协议，官方实现。  
  - **HARQ LDPC（draft-free）**：无 draft 模型的喷泉式 LDPC 基线。  
  - 消融中还对比了 **HARQ LDPC（带 draft，固定/2 的幂字母表）** 等中间变体。

- **主要指标**：  
  - 容量（正确恢复的负载位数 / 有效可见 token 数，bits per token）；  
  - 编码/解码吞吐（tokens/s）；  
  - 密钥交换的失效次数、失效概率上界、发布 token 数。

## 6. 论文的主要结论与发现

- Codetta 在三个工作负载、三个发送模型上实现了 **4.1–6.4×** 于 draft-free LDPC 基线、**16–94×** 于 ARS 的容量提升，最高达 0.5685 bits/token（Ministral 在 IFEval）。
- 所有 25 条消息均成功恢复，且记录的分布保持保证由定理证明；在 IFEval 上，隐写输出与普通输出在指令遵循准确性上无显著差异（最小 p 值 0.125）。
- 密钥交换在约 **81,920 可见 token** 内完成 128 位预密钥传输，大多数设置无失效；最差情况（Qwen 在 CTF）失效概率上界为 $4.1\times 10^{-3}$，最好情况为 $3.0\times 10^{-5}$。
- 消融显示：公共 draft 模型、自适应字母表大小、自适应 ECC 三部分各自贡献显著，组合后容量提升 4.8–6.4 倍。
- 结论：**有效不可检测的智能体共谋已具备现实可行性**，仅审计通信记录不足以防御，必须结合动作审计、可验证采样、信道扰动等补充手段。

## 7. 优点

- **可证明安全**：带密钥协议的不可检测性归结为 PRF 安全；密钥交换不可检测性归结为 MLWE 假设，且正确性有严格的数学定理和 BCH 确定性纠错保证。
- **高容量且保持分布**：通过 draft 模型估计信道和自适应字母表，显著提高容量，同时 maximal coupling 保证每步输出严格服从发送方分布，不泄露信息。
- **无密钥引导**：首次实现并实证评估了独立部署 LLM 智能体之间的隐写式密钥交换，解决了“需要密钥建立信道、需要信道建立密钥”的悖论。
- **在线自适应 ECC**：模块校验 + BP 解码支持任意字母表大小、自然码率自适应，且无需预先生成完整码字，契合自回归生成。
- **实验全面且包含消融**：三个工作负载、三个模型、多种消融，以及密钥交换的 100k 会话经验认证，提供了较完整的证据。
- **实际意义**：清晰展示了威胁的可行性，并给出了超越记录审计的防御方向讨论，具有现实安全警示价值。

## 8. 不足与局限

- **实验数据集与模型有限**：工作负载为合成或静态学术数据集，未在真实生产多智能体系统、更复杂的通信模式或更大规模闭源模型上验证；容量高度依赖文本熵，低熵任务（如 Qwen 在 CTF）容量骤降至 0.03 bits/token 以下。
- **密钥交换非端到端**：密钥交换的失效概率基于从候选池实测位移分布中独立采样的代数模拟，而非真实完整文本生成和传输；真实运行中位移可能具有时间相关性或依赖上下文，影响结论的稳健性。
- **安全假设**：不可检测性假设审计者是被动的、不修改或干扰信道；若审计者进行重写、扰动或主动修改，Codetta 可能被破坏。此外，安全证明依赖随机预言机模型和 MLWE 假设（NIST 安全类别 1），密钥交换的确认阶段若失败需重复，可能增加暴露风险。
- **容量未达理论极限**：虽然相比现有非对称方案提升显著，但与对称方案或理论熵上限相比仍有差距；BP 解码无严格纠错保证，依赖经验验证。
- **防御方案讨论初步**：文中提出的审计动作、可验证采样、信道扰动等防御方向未实现或评估，实际可行性未知。
- **偏差风险**：发送方模型均为开源、可访问权重；在闭源、API 受限或模型行为不可控的场景下，协议可行性可能不同；且隐写协议本身可能被检测器通过学习偏离特征发现（尽管本文证明不可区分，但实践中模型输出分布估计误差仍可能存在）。
