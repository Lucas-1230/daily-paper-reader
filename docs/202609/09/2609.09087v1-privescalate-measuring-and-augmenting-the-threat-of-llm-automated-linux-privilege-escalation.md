## 摘要
随着大语言模型（LLM）智能体在网络杀伤链中越来越多地自动化攻击行动，它们在复杂的本地后渗透任务中的有效性仍未被充分量化。其中，Linux 权限提升是初始访问与完全系统失陷之间的关键一步。然而，现有针对该任务的评估受限于样本规模较小（少于 15 个场景），缺乏在可执行验证下比较模型能力的规模。为此，我们提出 PrivEscalate，一个面向 Linux 权限提升的大规模基准，包含 531 个 Docker 化场景，涵盖 14 个子类别。我们另外衍生出 329 个参数化变体，以衡量对环境干扰因素的敏感性。对六种 LLM 在三种智能体架构上的评估表明：（i）模型能力在不同漏洞类别上存在异质性，在高频类别中没有任何单一模型占据主导，这促使需要进行多维度风险评估；（ii）LLM 的成功对环境扰动敏感，因此配置轮换可以干扰部分漏洞利用尝试，但并不能消除所测得的风险；（iii）智能体架构可以实质性改变成功率并重排模型排名，尽管其幅度因模型而异。利用这些见解，我们开发了 PrivEscAgent，这是一个领域专用的封装器，通过确定性枚举、类别匹配和步骤规划来增强通用 ReAct 智能体。PrivEscAgent 在未修改底层 LLM 的情况下，优于先前的 Linux 权限提升智能体基线。我们将 PrivEscalate 作为开源、Docker 化的测量工具发布，以支持 LLM 智能体评估、防御工具验证和红队训练。

## Abstract
As Large Language Model (LLM) agents increasingly automate offensive operations across the cyber kill chain, their efficacy in complex local post-exploitation tasks remains inadequately quantified. Among these, Linux privilege escalation is a key step between initial access and full system compromise. However, existing evaluations for this task are limited by small sample sizes (fewer than 15 scenarios), lacking the scale to compare model capabilities under executable verification. To address this, we present PrivEscalate, a large-scale benchmark for Linux privilege escalation, comprising 531 Dockerized scenarios spanning 14 sub-categories. We additionally derive 329 parameterized variants to measure sensitivity to environmental distractors.   Evaluating six LLMs across three agent architectures reveals: (i) model capability is heterogeneous across vulnerability classes, with no single model dominating across the high-prevalence classes, motivating multi-dimensional risk assessments; (ii) LLM successes are sensitive to environmental perturbation, so configuration rotation can disrupt some exploit attempts but does not eliminate the measured risk; and (iii) agent architectures can materially change success rates and reorder model rankings, though the magnitude is model-dependent. Leveraging these insights, we develop PrivEscAgent, a domain-specialized wrapper that augments a generic ReAct agent with deterministic enumeration, category matching, and step planning. PrivEscAgent improves over prior Linux privilege-escalation agent baselines without underlying LLM modifications. We release PrivEscalate as an open-source, Dockerized measurement instrument supporting LLM agent evaluation, defensive tool validation, and red-team training.

## 1. 论文的核心问题与整体含义

- **研究背景**：LLM 智能体正越来越多地自动化网络杀伤链中的攻击行动，其中 Linux 权限提升（privilege escalation）是从初始访问到完全系统失陷的关键一步。

- **整体含义**：该工作通过构建大规模、可复现的 Docker 化基准 PrivEscalate，对 LLM 自动化 Linux 权限提升的威胁进行系统量化，并进一步设计领域专用智能体 PrivEscAgent，展示仅通过智能体架构设计即可显著放大威胁，从而为防御者提供多维度的风险评估依据。

## 2. 论文提出的方法论

### 2.1 PrivEscalate 基准构建

- **分类体系**：  
  - 从 MITRE ATT&CK 枚举 Linux 相关提权技术，过滤 Docker 环境中不可复现的类别，并与 GTFOBins、Exploit-DB 交叉验证。  
  - 最终得到 14 个子类别，归为 5 大类：`Misconfig`（配置错误）、`Environ`（环境劫持）、`Sched`（计划任务）、`Cred`（凭证泄露）、`Cont`（容器逃逸）。

- **自动化构建管道**：  
  - **DataIngester**：将非结构化的漏洞描述（如 GTFOBins、Exploit-DB 条目）转换为统一的 `ScenarioSpec` 模板，必要时使用 LLM 进行可行性分类与解析。  
  - **Scaffolder**：基于模板生成一对 Dockerfile——`vulnerable`（注入目标漏洞）和 `fixed`（同一环境但移除漏洞），并应用基础加固以抑制非目标提权路径。  
  - **Exploiter**：生成 ground-truth 漏洞利用脚本，采用检索、适配、生成三种渐进模式。  
  - **Verifier**：执行三重验证——构建检查、漏洞利用差分检查、一致性检查，确保漏洞是唯一提权路径。  
  - **反馈循环**：验证失败时，Manager 模块将诊断信息分派给相应子代理进行修复并重新验证。

- **构建成果**：  
  - 从 1,067 个候选模板中验证成功 512 个（48.0%），经专家审计与补充后得到最终 531 个原始场景。  
  - 额外生成 329 个参数化变体，通过改变凭据、系统身份、枚举噪声、上下文噪声、环境指纹等五个轴来测试扰动敏感性。

### 2.2 PrivEscAgent 架构

- 在通用 ReAct 智能体（wintermute）之上封装四个模块：  
  - **PrivEnum**：确定性、无 LLM 的枚举模块，一次性收集 SUID、sudo、capabilities、cron 等提权证据，减少盲目探索。  
  - **CategoryMatcher**：将枚举输出映射到 ATT&CK 类别，规则匹配 + LLM 后备推理，输出候选利用策略排名。  
  - **StepPlanner**：对多步利用链进行分解，支持失败回滚。  
  - **StrategySelector**：基于置信度和历史成功率对候选策略排序，失败时自动切换策略，避免策略固定。

## 6. 论文的主要结论与发现

- **模型威胁排名（RQ1）**：  
  - 无单一模型在所有高频类别中占优：GPT-5.4 总体 SR 最高（40.9%）且在 SUID/SGID 类别领先，Claude Sonnet 4.6 在 Sudo 类别领先（46.1%）。  
  - 六模型联合覆盖 62.0% 的场景，远高于最佳单模型，说明单模型评估会低估暴露面。  
  - 失败主要源于选择了错误利用方法（占 81.6%），而非未尝试利用。

- **扰动敏感性（RQ2）**：  
  - 环境扰动导致 21.8%–41.0% 的已成功场景失败，保留率在 59.0%（GPT-5.4）到 78.2%（Claude Haiku 4.5）之间。  
  - 配置轮换可以部分缓解，但不能消除自动化提权风险。

- **架构影响（RQ3）**：  
  - HackSynth 提升了除 DeepSeek v3.2 外的五个模型，最大增益 +28.8 pp（Claude Sonnet 4.6）。  
  - 架构改变可以重排模型排名，且效果依赖模型类别（推理增强模型增益较小）。

- **成本与效率（RQ4）**：  
  - 成功运行通常较短（平均 7–10 步），部分模型 23%–29% 的成功在 ≤3 步内完成，检测窗口窄。  
  - 每成功成本随架构和模型差异极大，架构选择比模型本身对成本影响更大。

- **PrivEscAgent 效果**：  
  - 所有模型 SR 均提升，最弱的 Qwen-Plus 从 10.2% 提高到 39.5%，达到最强 wintermute 基线水平。  
  - 消融显示 `PrivEnum` 是最一致的贡献模块，对非推理模型贡献最大；对 GPT-5.4 则出现重塑而非单纯提升现象。

## 7. 优点

- **规模与可复现性**：531 个 Docker 化场景 + 329 个变体，远超前作；开源发布支持复现。

- **领域专用增强**：PrivEscAgent 展示不修改底层 LLM 也能大幅提升威胁，具有防御启示价值。  
- **统计严谨性**：使用 McNemar 检验、Pearson 相关、保留率等指标，并提供了审计流程和伦理声明。

## 8. 不足与局限

- **类别覆盖不均衡**：  
  - SUID/SGID（38%）和 Sudo（55%）场景占绝对多数，其他子类别场景极少（多数仅 1 个），导致细粒度结论的统计力不足。  
  - 排除了内核漏洞、NFS root squashing、服务特定 CVE、进程注入、boot/logon 触发等类别，覆盖不完整。

- **实验变异**：  
  - 大多数实验仅执行一次，虽然进行了重复性检查，但运行间变异未被充分纳入主要结果。  
  - 20 步预算可能高估简单场景的成功率、低估长链场景的潜力。

- **环境真实性**：  
  - Docker 环境与真实生产系统存在差异，例如内核相关漏洞无法复现，容器逃逸类场景受限。  
  - 构建管道依赖 LLM，可能存在系统性偏差，虽经审计缓解，但无法完全排除。

- **代理覆盖**：  
  - 仅比较了 ReAct、Planner-Summarizer 和自定义封装架构，未覆盖其他控制循环框架。  
  - 策略选择器使用了来自先前测量的类别先验，可能引入循环依赖。

- **应用限制**：  
  - 研究设计针对 LLM 智能体相对比较，而非与人类攻击者对比。  
  - 结论基于特定模型快照，可能随时间快速变化。
