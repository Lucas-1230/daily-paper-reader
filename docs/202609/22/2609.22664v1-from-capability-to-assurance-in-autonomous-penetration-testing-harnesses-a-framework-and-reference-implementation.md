## 摘要
针对渗透测试的大型语言模型智能体的研究几乎完全通过能力来评价：智能体是否夺得 flag 或复现概念验证。这一指标适用于基准测试，却无法说明自主智能体能否用于授权测试：所报告的发现是否真实、智能体是否停留在授权范围内、操作员能否审计其行为。我们称这些为保障属性，并认为它们属于执行环境——即包裹模型的运行时——且可在代码中强制执行。本文有三项贡献。首先，我们定义了一个包含五项保障属性的框架（证据锚定、非破坏性声明缩减、计算得出的严重性、强制授权和防篡改可问责性），每个属性都有形式化模型和明确验收测试，并与基于能力的安全、防篡改日志和软件溯源等先前工作相联系。其次，我们使用已发布的编码标准将代表性系统（PentestGPT、Cochise 参考执行环境、MAPTA 以及轨迹评判器 PentestJudge）置于该框架中，并识别出一致的保障缺口。第三，我们研究了一个开源实现 NeuroSploit，固定到具体提交，报告其架构、复杂性成本，以及针对一个公开的故意留有漏洞的目标运行得到的内容寻址工件包。我们直接执行确定性的授权和审计验收测试，发现并报告了一个真实的执行缺口，并据此将这两项属性评为部分实现。因此，我们提出的是一个初步的存在性论证，即这些属性可以共同实现，而非比较性性能结果；我们还给出了将框架义务转化为度量所需的多目标、消融和对抗性评估协议。

## Abstract
Research on large language model agents for penetration testing is evaluated almost entirely by capability: whether the agent captures a flag or reproduces a proof of concept. That metric suits a benchmark but is silent on the properties that decide whether an autonomous agent can be used in an authorized engagement: whether a reported finding is true, whether the agent stayed inside its authorized scope, and whether an operator can audit what it did. We call these assurance properties and argue that they belong to the harness, the runtime wrapping the model, and can be enforced in code. This paper makes three contributions. First, we define a framework of five assurance properties (evidence grounding, non destructive claim reduction, computed severity, enforced authorization, and tamper evident accountability), each with a formal model and an explicit acceptance test, connected to prior work in capability based security, tamper evident logging, and software provenance. Second, we position representative systems (PentestGPT, the Cochise reference harness, MAPTA, and the trajectory judge PentestJudge) within the framework using published coding criteria, and identify a consistent assurance gap. Third, we study one open source implementation, NeuroSploit, pinned to an exact commit, reporting its architecture, its complexity cost, and a content addressed artifact bundle from a run against a public deliberately vulnerable target. We execute the deterministic authorization and audit acceptance tests directly and find and report a real enforcement gap, which we reflect by scoring both properties as partial. We therefore claim an initial existence argument that the properties are realizable together, not a comparative performance result, and we specify the multi target, ablation, and adversarial evaluation protocol required to turn the framework obligations into measurements.

## 1. 论文的核心问题与整体含义

- **研究背景**：当前自主渗透测试 LLM 智能体的研究几乎全部以“能力”为评价标准——即是否夺得 flag 或复现 PoC。这类指标适合基准测试，但无法回答三个决定智能体能否用于真实授权渗透测试的关键问题：
  - 报告中的发现是否真实（Truth）；
  - 智能体是否停留在客户授权范围内（Authorization）；
  - 事后能否审计其行为（Accountability）。
- **核心论点**：这些“保障属性”属于**执行环境（harness）**，而非模型权重本身；它们可以在代码中强制执行，而不是仅仅通过提示词请求模型遵守。
- **研究问题**：
  - **RQ1**：自主渗透测试执行环境应提供哪些保障属性？能否将每个属性表述为与实现无关、且带明确验收测试的义务？
  - **RQ2**：在客观、可编码的标准下，现有代表性系统处于什么位置？
  - **RQ3**：这些属性能否在单一系统中共同实现？复杂度成本如何？需要怎样的评估协议来度量其满足程度？
- **贡献定位**：本文不是性能比较论文，而是一个**初始存在性论证**——证明五项保障属性可以共同实现，并给出将其转化为可度量指标的评估方案。

## 2. 论文提出的方法论

- **总体框架**：定义五个保障属性 **P1–P5**，每个属性包含：
  - 形式化模型（用集合、逻辑或公式表达）；
  - 明确的验收测试（确定性的、可执行的检查）。

- **五个属性具体内容**：

  - **P1 — 证据锚定（Evidence grounding）**
    - 要求任何声称（claim）都必须有模型外部的决策程序认可的“证据收据（receipt）”。
    - 决策程序 `supports` 返回 `Confirmed / Rejected / NeedsReview`，模型意见不算证据。
    - 验收测试：注入伪造但语法合理的收据，断言其不能进入“已确认”状态。

  - **P2 — 非破坏性声明缩减（Non-destructive claim reduction）**
    - 夸大声明应缩减到证据支持的范围，但不能静默删除或强行保留。
    - 将声明分解为“有证据支持的机制”和“无证据支撑的影响”，返回四种类型化结果：支持性发现、信息性观察、证据不足、无效声明。
    - 验收测试：已证明机制但影响未证明的发现应被保留并降级，而非拒绝；两者皆无的声明不得强行保留。

  - **P3 — 计算得出、按证据分级、影响分离的严重性（Computed severity）**
    - 严重性必须由确定性函数基于 CVSS v3.1 计算，并由**已证明的影响等级**封顶（`reached < read < wrote < RCE < crossed`）。
    - 已证明严重性 `sev_d` 与潜在严重性 `sev_p` 分别记录，避免因安全起见未演示破坏性影响而低估风险。
    - 验收测试：两个相同 CWE、但已证明影响不同的发现必须得到不同的 `sev_d`。

  - **P4 — 强制且可归因的授权（Enforced authorization）**
    - 授权是签名能力令牌，绑定客户端、操作员、任务和资产集；会话内行为只能收窄不能扩大授权范围，并具备重放与撤销控制。
    - 准入条件形式化为令牌验证、时间窗口、新鲜性、受众匹配与 `(target, action) ⊑ A` 的包含关系。
    - 验收测试：对抗性范围攻击（重定向、DNS 重绑定、备用 IP 编码、通配符过宽、过期/篡改令牌等）必须全部被拒绝。

  - **P5 — 外部锚定的防篡改可问责性（Tamper-evident accountability）**
    - 每个动作以追加式日志记录，通过哈希链 `h_i = H(r_i ∥ h_{i-1})` 保证完整性。
    - 单纯哈希链只能检测本地篡改，需定期外部锚定（外部签名、可信时间戳、一次写入存储或透明日志）以抵御全量重写攻击。
    - 验收测试：记录删除、修改、重排、证据替换、令牌交换、日志截断、整链重建均须检测；最后一项仅在启用锚定时通过。

- **威胁模型**：定义四类威胁 T1–T4（模型幻觉、目标提示注入、范围漂移、事后争议），框架结构性应对 T1、T3、T4，而 T2 仅被缓解而非消除。

- **参考实现 NeuroSploit**：
  - Rust 编写的开源执行环境，管线为：侦察 → 信念状态 → 表面匹配的智能体选择 → 模型池并行运行 → 验证管线 → 链接与报告。
  - **P1–P3 实现**：证据锚定、27 个确定性按 CWE 验证器（覆盖 31 个 CWE）、多模型对抗投票、证据检控官。
  - **P4–P5 实现**：签名能力令牌、两层范围守卫（硬范围 + 软范围）、哈希链审计日志。
  - 计划层使用信息价值决策（公式 `V_obs(b) > V_exploit(b)`）作为防幻觉门控。

## 6. 论文的主要结论与发现

- **保障属性可实现性**：五个保障属性可以在同一执行环境中通过代码共同实现，NeuroSploit 是初步存在性证据。
- **现有系统存在一致保障缺口**：代表性系统几乎只覆盖能力或轨迹级评判，而在发现级真实性、强制范围和逐动作问责方面缺失（见表 I）。
- **发现真实执行缺口**：通过直接执行 P4 验收测试，发现当运行主目标位于授权范围之外时，该实现仍会侦察该目标并在日志中记录为 allow，而未被拒绝。
- **精度–召回权衡**：严格的证据规则会提高精度但牺牲召回，`testphp` 的零确认结果即为实例；精确的权衡需由未来协议量化。
- **评估协议缺失是核心开放问题**：论文提出多目标、消融和对抗性评估协议（附录 H），将框架义务转化为度量。

## 7. 优点

- **概念清晰且可操作**：将保障属性从模糊的“可靠性”转化为五个带形式化模型和验收测试的义务，可直接在代码中检查。
- **强调“执行环境而非模型”**：将保证责任从模型权重转移到可代码审计的 harness，工程意义明确。
- **方法论客观**：使用已发布的编码标准定位现有系统，并提供附录 I 的评分协议，可复现、可争议。
- **诚实与透明**：主动披露竞争利益、如实报告负面结果、未填充的 CVSS 向量、审计日志缺失以及 P4 缺口，增强可信度。
- **内容寻址工件包**：提供版本固定、内容寻址的工件包和 SHA-256 根哈希，便于独立验证。
- **安全基础深厚**：将属性与能力安全、Macaroons/JWT、哈希链、Certificate Transparency、in-toto 溯源等成熟理论联系，理论根基扎实。

## 8. 不足与局限

- **无保障属性基准**：没有共享、公开的基准用于测量真实性、范围执行和可审计性，因此无法进行排名或比较性能评价。
- **实验覆盖面窄**：仅一次完整黑盒运行、一次负面运行；未执行多目标、多轮、消融和对抗性完整评估；附录 H 的协议仍待完成。
- **潜在记忆偏差**：目标 `testaspnet.vulnweb.com` 是广泛使用的公开应用，可能出现在模型训练数据中，导致召回率虚高；负面结果部分缓解此担忧，但外部效度有限。
- **P4 缺口**：主目标超出授权范围时未被拒绝，是具体执行漏洞；作者承认这是实现欠账。
- **P5 未完全实现**：哈希链已存在并测试，但外部锚定仍停留在设计层面，因此无法抵御全量重写攻击。
- **P3 档案缺失**：档案运行的 CVSS 向量字段为空，P3 的证据来自代码和单元测试，而非本次运行。
- **T2 未消除**：提示注入无法完全根除，P1 限制后果但计划层仍是攻击面，命令隔离仅部分实现。
- **令牌强度有限**：P4 当前 HMAC 形式只能证明密钥持有，无法证明客户意图；推荐的非对称签名演进尚未实现。
- **精度优先可能误报漏报**：严格证据规则会抑制真实漏洞（如 `testphp` SQL 注入），对真实客户报告可能过于保守。
