## 摘要
语言模型智能体越来越多地使用工具来作用于外部系统。先前的动作可能会改变文件、权限、数据库记录或其他状态，使后来看起来常规的动作变得有害。然而，可见的交互可能无法揭示评估该动作所需的底层状态。我们在 SEAD 中将攻击和防御形式化为部分可观测状态控制，从这一共享执行过程中推导出它们的设计要求。由于攻击者提供指令而目标选择具体动作，DART 将有害目标分解为局部合理的步骤，并利用实际工具执行的反馈来引导轨迹搜索。防御者必须在执行前依据不完整的状态证据做出决定。因此，SAGE 可以通过只读查询调查相关状态，然后再允许或阻止每个动作，包括在阻止之后提出的动作。我们构建了一个可由环境验证的数据集，集成了受控初始状态、可回放的工具环境以及任务特定的可执行检查。在四个目标模型上，DART 将语义攻击成功率相较于竞争基线提高了 18.8–35.9 个百分点，并且在可执行验证下取得一致的提升。在记录的轨迹上，SAGE 保留了 95.79% 的良性轨迹，同时在危害促成边界拦截了 92.73% 的有害路径。在在线攻击-防御评估中，它将 DART 的可执行攻击成功率从 48.0% 降低到 4.0%。SAGE 在四种攻击方法下仍然有效，并能泛化到域外环境。我们的代码和数据可在 https://github.com/EverywhereSafety/SEAD 获取。

## Abstract
Language-model agents increasingly use tools to act on external systems. Earlier actions can alter files, permissions, database records, or other state, making a later routine-looking action harmful. Yet the visible interaction may not reveal the underlying state needed to assess that action. We formulate attack and defense as partially observed state control in SEAD, deriving their design requirements from this shared execution process. Because attackers supply instructions while the target chooses concrete actions, DART decomposes harmful goals into locally plausible steps and uses feedback from actual tool execution to guide trajectory search. The defender must decide before execution with incomplete state evidence. SAGE can therefore investigate relevant state through read-only queries before allowing or blocking each action, including those proposed after a block. We construct an environment-verifiable dataset integrating controlled initial states, replayable tool environments, and task-specific executable checks. Across four target models, DART improves semantic attack success by 18.8--35.9 percentage points over the competing baseline, with consistent gains under executable verification. On recorded trajectories, SAGE preserves 95.79% of benign trajectories while intercepting 92.73% of harmful paths by the harm-enabling boundary. In online attack-defense evaluation, it reduces DART's executable attack success from 48.0% to 4.0%. SAGE remains effective across four attack methods and generalizes to out-of-domain environments. Our code and data is available at https://github.com/EverywhereSafety/SEAD.

## 1. 论文的核心问题与整体含义

- **研究背景**：语言模型智能体越来越多地通过工具作用于外部系统，如修改文件、权限、数据库记录等。早期动作会改变环境状态，使后续看似常规的动作可能在特定状态下变得有害。
- **核心问题**：可见的对话与工具交互历史往往不足以揭示评估动作安全所需的底层状态；同一动作在不同状态下可能完全无害，也可能完成有害目标。攻击者、目标智能体和防御者各自只能观察到部分、角色特定的证据。
- **整体含义**：智能体安全不再只是“回答是否合规”，而是“动作轨迹及其达到的环境状态是否安全”。论文将攻击、防御与评估统一到一个**部分可观测状态控制**框架 SEAD（State-grounded Execution for Attack and Defense）中，强调持久化状态、部分可观测性和执行反馈三个要素的共同作用。
- **设计动机**：
  - 攻击者只能提供指令，目标智能体决定具体动作，因此攻击方法必须适应真实执行结果，而非假设每个预期步骤都会发生。
  - 防御者必须在动作执行前用不完整证据做出 PASS/BLOCK 决定，因此可能需要主动调查相关状态。
  - 防御者的干预会改变后续交互，因此评估必须覆盖“被阻止后目标重新规划、攻击者修改指令”的在线动态过程。

## 2. 论文提出的方法论

### 2.1 SEAD：部分可观测状态控制形式化

- 将环境建模为 `(S, U, O, F, Ω, s0)`，其中状态 `s` 包含文件、权限、数据库记录等；动作 `u` 是工具调用；`F` 是状态转移函数；`Ω` 返回可见工具反馈。
- 三个角色共享同一执行循环：
  - 攻击者提供指令 `x`；
  - 目标智能体基于自身历史提出工具动作 `u`；
  - 防御者 `ΓD` 接收自身可见历史和待执行动作，可选收集证据后返回 `PASS` 或 `BLOCK`。
- 若 `PASS`，环境状态按 `F(s,u)` 更新并返回观测；若 `BLOCK`，状态不变，返回拒绝反馈 `o_BLOCK`。被阻止的动作也会计入后续交互历史。
- **有害目标与边界**：用 `Hg(s)=1` 表示状态 `s` 已完成有害目标 `g`。定义 `βg(s,u)=1` 表示在状态 `s` 执行动作 `u` 使目标从尚未完成变为已完成，即“危害促成转移”。识别这一边界是精准防御的关键。
- **状态模糊性**：若存在两个兼容于防御者证据的状态 `sa, sb`，但同一动作在二者上分别需要 PASS 和 BLOCK，则仅凭可见历史无法可靠决策。这从理论上说明：**防御者需要额外状态证据**。

### 2.2 DART：基于执行反馈的攻击方法

- **全称**：Decomposed Attacks with Runtime Feedback and Tree Search。
- **核心思想**：将有害目标分解为局部合理、单独看似无害的步骤，并利用目标真实执行的结果来指导搜索，而不是预先固定攻击路径。
- **算法流程**：
  - 在已执行轨迹前缀上构建搜索树，每个节点代表一个真实的执行前缀及其到达的状态。
  - 从父节点生成多个候选指令，每个候选描述一个预期的中间状态变化；这些候选作为兄弟分支，实际执行结果决定子节点。
  - 每个节点的价值初始化为：
    \[
    Q_v \leftarrow 0.20 I_v + 0.30 C_v + 0.50 P_v
    \]
    其中 `Pv` 是可执行验证器给出的任务进展，`Iv` 是内省评分（评估指令是否有用），`Cv` 是执行反馈评分（评估观察到的执行结果是否有信息量）。
  - 使用 **UCT** 选择待扩展前缀：
    \[
    \text{UCT}(p,v)=Q_v + 1.414\sqrt{\frac{2\log\max\{1,N_p\}}{N_v}}
    \]
    平衡已有价值估计与探索。
  - 路径终止条件包括：确认完成、连续重复指令/拒绝/空操作、达到最大深度、搜索预算耗尽。
  - 终端回报根据进展和终止原因计算：`G = clip[-1,1](P + δ)`，其中 `δ` 对冗余、拒绝、超深度等给予负惩罚，并沿路径回传更新节点价值。
- **完成标准**：
  - **Hard success**：使用任务特定、环境可验证的可执行检查器验证最终状态。
  - **Semantic success**：由独立 LLM Judge 根据记录的执行证据，对照任务检查点进行语义判断。
- 两种标准互不替代，用于分离“进展评分”和“最终完成验证”。

### 2.3 SAGE：状态感知的预执行防御

- **全称**：State-Aware Gating through Exploration。
- **核心思想**：在决定是否放行一个待执行动作之前，防御者可以通过**只读、非干扰查询**主动收集相关状态证据，以便区分无害准备步骤与有害边界转移。
- **算法流程**：
  - 给定防御者可见历史 `hDn` 和待执行动作 `un`，防御者可以选择进行多次只读查询：
    \[
    q_k \sim \pi_D^{query}(\cdot \mid hD_n, u_n, \eta_{k-1}),\quad oD_k \sim O_D(\cdot \mid s_n, q_k)
    \]
  - 查询结果加入私有调查记录 `ηk`，但**不修改被保护的任务状态**，且对其他角色不可见。
  - 在查询预算 `K` 内，防御者停止调查后作出最终决策：
    \[
    d_n \sim \pi_D^{dec}(\cdot \mid hD_n, u_n, \eta_\kappa),\quad d_n\in\{\text{PASS},\text{BLOCK}\}
    \]
- **训练**：通过监督微调生成包含可选查询和最终决策的防御者轨迹。参考标签将良性动作和有害闭包之前的前置动作标为 `PASS`，将首次完成有害
