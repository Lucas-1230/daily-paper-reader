## 摘要
大语言模型（LLMs）已被滥用于生成恶意软件，但针对代码生成安全的护栏有效性仍不明确。我们提出 CS-Guard，这是首个系统评估代码生成安全护栏的基准。它涵盖：1）文本到代码生成，包含 1000 条高质量恶意软件生成提示、7 种越狱攻击，以及一种新颖的虚构场景攻击（FSA），将恶意意图嵌入合法的虚构软件开发场景中；2）代码到代码生成，包含 331 条代码提示，涵盖代码填充、代码补全和代码翻译。我们在 7 个大语言模型上实证评估了 9 种护栏。我们发现当前护栏对恶意代码生成请求的防护效果较差：在文本到代码任务中，许多护栏在越狱后的平均攻击成功率（ASR）约为 50%；在代码到代码任务中，基础大语言模型的平均 ASR 接近 100%，且在许多护栏下仍保持较高水平（14.4% 至接近 100%）。我们的 FSA 在许多护栏下也达到接近 100% 的 ASR，对现实软件开发提出了重大可靠性担忧。为支持未来研究，CS-Guard 采用模块化的三层护栏分类体系，开发者可注册护栏进行评估。我们公开该基准与数据，以促进社区进一步评估。

## Abstract
Large language models (LLMs) have been ex- ploited to generate malware, but the effective- ness of guardrails for code generation secu- rity remains unclear. We introduce CS-Guard, the first benchmark to systematically evalu- ate guardrails for code generation security. It covers 1) text-to-code generation with 1000 high-quality malware-generation prompts, 7 jailbreak attacks, and a novel fictional scenario attack (FSA) that embeds malicious intent in a legitimate fictional software-development sce- nario; and 2) code-to-code generation with 331 code prompts spanning code infilling, code completion, and code translation. We empiri- cally evaluate 9 guardrails across seven LLMs. We find that current guardrails perform poorly against malicious code-generation re- quests: for text-to-code, the average attack success rate (ASR) after jailbreaks reaches about 50% for many guardrails; for code-to- code, average ASR approaches 100% on base LLMs and remains high across many guardrails (14.4% to nearly 100%). Our FSA also achieves ASR close to 100% across many guardrails, raising major reliability concerns for real-world software development. To sup- port future research, CS-Guard uses a modular three-layer guardrail taxonomy that lets devel- opers register guardrails for evaluation. We release the benchmark and data to enable fur- ther community evaluation.

# CS-Guard 论文总结

## 1. 论文的核心问题与整体含义

- **研究背景**：大语言模型（LLMs）越来越多地作为代码代理部署在软件开发环境中，能够完成代码编辑、指令到代码生成、代码翻译等任务；但同时，LLMs 也被滥用于生成恶意软件，已出现真实黑客利用 LLM 制售恶意软件的案例。
- **核心问题**：现有 LLM 安全护栏（guardrails）对恶意代码生成请求的防护效果究竟如何，缺乏系统、细粒度的评估。此前的安全基准大多把恶意软件生成作为宽泛风险分类中的一个小类，评估粒度较粗，且多聚焦自然语言指令，忽略了代码代理同时处理自然语言与代码的特点。
- **整体含义**：CS-Guard 是首个专门针对代码生成安全护栏的系统性基准，目的是建立一个标准化、可复现的测试平台，暴露当前护栏在恶意代码生成场景下的薄弱环节，为后续研究提供基础。

## 2. 论文提出的方法论

- **总体设计原则**：
  - 覆盖两个代表性代码生成场景：**文本到代码生成**（自然语言指令生成恶意代码）和**代码到代码生成**（输入含恶意代码片段，模型继续生成代码）。
  - 采用模块化、可扩展的三层护栏分类体系，便于研究者注册和评估新护栏。

- **文本到代码评估**：
  - **Level 1 基础提示评估**：使用 CyberSecEval 提供的 1000 条高质量 TTP（ATT&CK 技术、战术与流程）恶意软件生成提示，测试护栏对直接恶意请求的基本识别能力。
  - **Level 2 越狱攻击增强评估**：在基础提示上应用 7 种代表性越狱攻击：CipherChat、EmojiAttack、FlipAttack 三种混淆类攻击，以及 UCAR、EvilConfident、AIM、DevmodeRanti 四种模板类攻击，评估护栏对隐蔽恶意意图的鲁棒性。

- **虚构场景攻击（FSA）**：
  - **核心思想**：恶意软件与合法软件往往共享功能需求，区别仅在使用意图。FSA 将恶意功能需求嵌入一个看似合法的虚构软件开发场景中，例如将 bootkit 伪装成“远程启动救援代理”。
  - **单轮 FSA 构建**：先从每个 TTP 提示中提取功能行为，用 GPT5-mini 生成合法应用场景（名称、使用场景、功能对应关系），再让未审查的 LLM（Venice-uncensored-1.1）扮演网络犯罪分子，生成嵌入恶意目标的攻击提示。最终得到 1000 条 FSA-full 和 300 条 FSA-small。
  - **多轮 FSA（FSA-MT）**：将单轮 FSA 提示分解为若干自适应子指令，采用树状思维深度优先搜索（ToT-DFS）进行状态搜索。每一步采样 5 个候选指令，由 LLM 模拟 5 轮对话评估其可行性，选择完成概率最高的候选；每轮受害 LLM 生成 5 个响应，若全部拒绝则终止，否则继续，5 轮后由 LLM 判断是否已解决原始提示。论文提供了 20 条多轮样本用于概念验证。

- **代码到代码评估**：
  - 收集 331 条代码提示：来自 RMCBench 的 80 条代码填充、91 条代码翻译提示，以及来自 Redcode-Gen 的 160 条代码补全提示。
  - 不施加额外的越狱增强，主要考察护栏对包含恶意源代码输入的检测能力。

- **护栏分类与选择**：
  - **分类层**：strategy-type（依赖基础 LLM 实时生成）、classifier-type（独立检测模型）、internal-type（部署前嵌入 LLM，如安全对齐）。
  - **操作层**：classification（分类恶意内容）、generation（控制生成过程产生更安全响应）。
  - **位置层**：input（提示输入前检测）、output（结合响应判断是否越狱）、flexible（不依赖单一位置，如生成操作型护栏）。
  - 选择了 5 种策略型护栏（SmoothLLM、RPO、PAT、Parden、SelfReminder）、5 种分类器型护栏（Qwen3Guard-Gen、Llama-Guard4、WildGuard、NemoGuard、MD-Judge），以及 7 个具备安全对齐的 LLM 作为内部型护栏。

- **评估流程与指标**：
  - 使用 vLLM 推理，生成上限 14500 token；每提示采样 5 个响应，只要有一个被判定为恶意输出即视为越狱成功。
  - LLM 自动标注器对响应标注 good/bad/unclear，再通过多数投票确定最终标签；同时进行人工标注验证自动标注器的准确性。
  - 主要指标：输入位置护栏用攻击成功率（ASR）；策略型护栏用应用后的 ASR 降低值；输出位置护栏用 F1 值。

## 3. 实验设计

- **数据集与场景**：
  - 文本到代码：1000 条 TTP 恶意提示（基础 Level 1）；7 种越狱攻击；1000 条 FSA 单轮提示（含 300 条小规模版本）；20 条多轮 FSA 概念验证样本。
  - 代码到代码：331 条提示，覆盖代码补全、代码填充、代码翻译三类任务。
  - 数据来源：CyberSecEval、RMCBench、Redcode-Gen，均为公开数据集。

- **对比方法**：
  - 7 个 LLM：CodeLlama-13B、GPT-OSS-20B、Devstral-small-v2-24B、DeepSeekCoder-V2-Lite-16B、Qwen3-30B、Qwen3-Coder-30B、GPT5-mini。
  - 5 种策略型护栏、5 种分类器型护栏，以及模型自身的安全对齐（internal-type）。

- **人类验证**：
  - 对文本到代码 Level 1、Level 2 和代码到代码分别人工抽样标注 97、98、97 条样本，验证 LLM 自动标注器准确率分别为 96.8%、93.8%、93.7%。
