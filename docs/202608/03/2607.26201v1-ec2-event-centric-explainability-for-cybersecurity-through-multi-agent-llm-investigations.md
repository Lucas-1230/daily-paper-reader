## 摘要
安全运营中心依赖异常检测系统来标记可疑事件。异常检测器的特征级解释对于运营调查的价值有限。为了有效处理告警，分析师需要了解上下文关系，并对涉及的实体有可操作的理解。本文介绍了一种以事件为中心且与检测器无关的方法，用于解释中小型企业网络中的网络安全告警。我们提出了(EC)2，一个多智能体框架，该框架执行结构化、假设驱动的调查，以提供基于可验证证据的解释。评估结果表明，所提出的框架通过生成在运营上有意义的解释，改进了检测后分析，同时也提高了事件分类的准确性。

## Abstract
Security operations centers rely on anomaly detection systems to flag suspicious events. Feature-level explanations for anomaly detectors offer limited value for operational investigations. To effectively handle alerts, analysts need to know contextual relationships and need actionable understanding of the entities involved. This paper introduces an event-centric detector-agnostic approach for explaining cybersecurity alerts in small- to medium-sized enterprise networks. We present (EC)2, a multi-agent framework that performs structured, hypothesis-driven investigation to provide explanations grounded in verifiable evidence. Evaluation results show that the proposed framework improves post-detection analysis by generating operationally meaningful explanations, which also enhance event classification accuracy.

### 3. 实验设计

*   **数据集**：采用网络安全领域公开基准数据集 **CSE-CIC-IDS2018**，包含7种攻击类别（暴力破解、DoS/DDoS、Web攻击、僵尸网络、心脏滴血、渗透攻击）和正常背景流量，数据来源为约12亿个原始数据包。
*   **对比基准与实验方法**：
    1.  **对比基准方法 (RQ1)**：对比了业界领先的基于大语言模型的网络入侵检测可解释性框架 **eX-NIDS**。该方法通过一次性提示工程（将增强的 NetFlow 记录提交给大语言模型）来生成解释。
    2.  **评估标准**：从 eX-NIDS 公开的解释中随机选取50个事件，由同一个配置为“高级安全分析师”的 GPT-5.1 大语言模型评估器，基于真实攻击数据对两者的解释进行1-5分的三个维度打分：
        *   **攻击类型识别**：是否正确识别攻击类别。
        *   **实体识别**：是否正确识别攻击者/受害者IP及角色。
        *   **解释完整性**：是否完整捕捉了多阶段攻击链及正确时序。
    3.  **消融实验 (RQ2)**：在相同50个事件上，分别移除(EC)2的关键组件（初始化智能体、规划器、数据库访问、审阅器）或单一数据源（仅拓扑/仅流量），以评估各组件的贡献度。
    4.  **检测增强实验 (RQ3)**：使用无监督异常检测器 AE-IDS 在完整数据集上运行，定位其“不确定区域”（即距离决策边界最近的5%的NetFlow记录）。从中分层采样1000条记录（500恶意/500良性），用(EC)2对它们进行调查，再由一个大语言模型仅基于调查解释进行二分类（恶意/良性），观察分类性能（召回率、精确率、假阳性率）的提升。

### 6. 主要结论与发现

*   **(EC)2的解释质量显著优于基准**：在所有三项评估标准（攻击类型识别、实体识别、解释完整性）上，平均分均大幅超越 eX-NIDS。例如，在“攻击类型识别”上，\((EC)^2\)得分为3.21，而eX-NIDS仅为1.49。
*   **证据检索是核心支柱**：消融实验表明，移除数据库访问导致性能下降最严重，其他核心智能体（规划器、初始化）的移除也导致显著性能下降，证明了框架各环节设计的必要性。拓扑和流量两类数据源缺一不可，但流量数据更为关键。
*   **(EC)2能增强检测能力**：在AE-IDS不确定性最高的边界案例上，使用(EC)2的解释进行重分类，召回率从0.54提升至0.72，精确率从0.56提升至0.73，假阳性率从0.43降至0.26，证明了该方法不仅能解释，还能辅助提升检测准确性。

### 7. 优点

*   **范式创新**：实现了从解释“模型为什么报警”到解释“事件为什么可疑”的转变，更贴近分析师的实际调查需求。
*   **架构可扩展性**：多智能体、检测器无关的设计使其可适配任何异常检测器。新增数据源只需增加检索智能体并更新`证据收集智能体`的工具，无需改动其他智能体。
*   **证据驱动与可追溯**：通过 RAG 机制和结构化的对话流程，所有推理步骤都锚定在可验证的外部数据上，极大提升了可信度并抑制了大语言模型幻觉。
*   **操作实用性**：生成的不是枯燥的特征分数，而是一份结构完整的、可以呈现给人类分析师的调查手记，支持分析师对支持、反驳、未解决的多种假设进行最终人工判断。

### 8. 不足与局限

*   **高延迟与高成本**：单次调查耗时17分钟，虽然可并行，但显然不适用于大规模实时告警流的场景，更适合用于高优先级告警的深度复盘。
*   **数据源依赖与构建成本**：框架高度依赖预构建好的网络拓扑知识图谱和结构化的流量数据库。在现实网络中，建立和维护这些数据源本身是一项复杂的工程任务。
*   **评估的局限性**：
    *   主要评估仅在一个模拟数据集（CSE-CIC-IDS2018）上进行，其结果向真实、动态变化的中小企业网络环境的泛化能力有待验证。
    *   仅与一个重要基准（eX-NIDS）进行了对比，但两者输入格式不同（\( (EC)^2 \)接收原始事件，eX-NIDS接收NetFlow）。\( (EC)^2 \)能够访问更底层的数据，这可能构成了不公平的优势。
    *   评估依赖于大语言模型法官，虽然其一致性得到了验证，但仍可能存在偏见。
