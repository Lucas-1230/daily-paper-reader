## 摘要
大语言模型智能体越来越多地连接到高价值资源，如计算基础设施、凭据、使用预算、身份、私有知识、通信渠道和组织工作流。现有的智能体安全研究主要研究针对指令、数据和工具行为的攻击，而智能体可访问的高价值资源作为直接攻击目标受到的关注要少得多。我们首次识别并系统研究了智能体资源劫持，这是一个安全盲点，攻击者诱导智能体调用、消耗、转移或控制高价值资源以实现自己的目标，而无需直接获取这些资源或其凭据。为研究这一威胁，我们引入了 ResourceHijackBench 以及一个用于生成资源劫持案例的自动化流水线。我们将智能体的高价值资源组织为六个类别，并构建了300个攻击场景和900条攻击提示。每个案例在隔离的本地环境中运行，记录实际资源使用情况，从而可以从智能体行为而非仅文本响应来评估攻击。在没有额外防御的情况下，OpenClaw 的平均攻击成功率达到84.06%。该攻击在不同的模型后端下仍然有效，平均成功率在69.98%到89.58%之间。现有防御降低了部分风险，但所评估的最强防御仍留下55.11%的平均攻击成功率。这些结果表明，智能体可访问的高价值资源构成了一个重要且此前被忽视的攻击面，并且当前的智能体防御不足以保护它们免受资源劫持。

## Abstract
Large language model agents are increasingly connected to high-value resources such as computing infrastructure, credentials, usage budgets, identities, private knowledge, communication channels, and organizational workflows. Existing agent security research mainly studies attacks on instructions, data, and tool behaviors, while high-value resources accessible to agents have received much less attention as direct attack targets. We are the first to identify and systematically study agent resource hijacking, a security blind spot in which attackers induce agents to invoke, consume, transfer, or control high-value resources for their own goals without directly obtaining those resources or their credentials. To study this threat, we introduce ResourceHijackBench together with an automated pipeline for generating resource hijacking cases. We organize high-value agent resources into six categories and construct 300 attack scenarios with 900 attack prompts. Each case runs in an isolated local environment that records actual resource use, allowing attacks to be evaluated from agent behavior rather than text responses alone. Without additional defenses, OpenClaw reaches an average attack success rate of 84.06%. The attack remains effective across different model backends, with average success rates ranging from 69.98% to 89.58%. Existing defenses reduce part of the risk, but the strongest evaluated defense still leaves an average attack success rate of 55.11%. These results show that high-value resources accessible to agents form an important and previously overlooked attack surface, and that current agent defenses are not sufficient to protect them from resource hijacking.

## 1. 论文的核心问题与整体含义

- **研究背景**：LLM 智能体正从纯文本生成走向自主执行真实操作，常被授予高价值资源访问权限，如计算基础设施、API 密钥、身份权限、私有知识、通信渠道与组织工作流。
- **核心问题**：现有智能体安全研究主要关注指令注入、有害内容、数据泄露和危险工具调用，但很少把智能体可访问的“高价值资源本身”作为直接攻击目标。
- **提出威胁**：论文首次系统研究 **资源劫持（Agent Resource Hijacking）**——攻击者不直接窃取资源或凭据，而是诱导智能体代表攻击者调用、消耗、转移或控制高价值资源。
- **整体含义**：即使智能体拒绝泄露 API Key、GPU 访问权限等敏感信息，仍可能被利用来消耗配额、运行攻击者工作负载、冒用身份或调动组织流程，构成一个被忽视的重要攻击面。

## 2. 论文提出的方法论

- **核心思想**：将高价值资源本身作为攻击目标，而非只关注指令、数据或单次工具调用；通过“任务来源、资源所有者、允许用途、实际受益者”之间的不一致来识别资源劫持。
- **资源分类法**：借鉴资源保存理论、社会资源理论和资本/社会资本理论，将智能体资源划分为 6 类：
  - **Material（物质）**：GPU、CPU、内存、带宽、容器、CI runners 等。
  - **Condition（条件）**：API key、OAuth token、IAM 角色、仓库权限、部署权限等。
  - **Energy（能量）**：模型调用配额、CI 分钟数、云预算、请求额度等。
  - **Social and symbolic（社会与符号）**：维护者身份、提交署名、发布身份、官方账号等。
  - **Information and knowledge（信息与知识）**：私有代码、内部文档、长期记忆、知识库等。
  - **Interaction（互动）**：团队通信、公司邮箱、审批链、组织工作流等。
- **自动化案例生成管线**：
  - 在 6 个资源类别语义空间内，使用 constrained LLM 自动发现具体资源目标、正常用途、劫持目标、工作流上下文、预期调用路径和资源使用线索。
  - 每个场景生成 1 个完整案例 + 3 个提示变体，变体共享资源目标但采用不同任务设置和措辞。
  - 生成结果通过固定验证规则检查 JSON 格式、字段完整性、重复性、真实 URL/邮箱/凭据等过滤。
- **攻击设置**：
  - **Implicit requests**：将资源使用隐藏在开发、维护或研究任务中。
  - **Direct requests without confirmation**：明确要求资源操作，但不确认允许范围、成本或敏感边界。
  - **Persistent-context attacks**：将资源使用指令放入项目记忆、工作流文档等持久上下文，稍后由正常任务触发。
- **评估方法**：每个案例在隔离的本地模拟环境中运行，记录实际工具调用和环境状态变化；使用 LLM-based judge 结合日志判断目标资源是否被成功劫持，而非仅依赖文本响应。
