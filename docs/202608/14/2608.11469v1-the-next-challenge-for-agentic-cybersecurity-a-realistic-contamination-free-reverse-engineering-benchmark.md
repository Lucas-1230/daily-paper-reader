## 摘要
当源代码可供分析时，AI智能体在网络安全能力方面正在迅速提升；然而，对网络安全最为关键的许多软件（包括恶意软件、固件和专有应用程序）仅以二进制形式提供。分析此类软件需要逆向工程（RE）：在能够有意义地进行分析之前恢复程序语义。然而，评估智能体逆向工程面临一个根本性挑战：基准实例必须作为源代码在LLM的训练数据中不可见，以防止模型通过识别它们而非真正分析它们来走捷径，同时还要匹配真实软件的规模和反分析保护。不幸的是，现有基准并未同时满足这些要求。为此，我们引入了SRE-Bench，这是第一个真实、无污染的逆向工程基准。SRE-Bench由逆向工程专家完全从零开始构建，耗时超过5000小时，包含19个私有的、真实世界规模的程序，平均代码行数为16.9K行。我们进一步开发了44个内部反分析原语，产生了262个二进制实例和1572个确定性评分任务。我们对五个前沿LLM（GPT-5.6-sol、Claude-Opus-5、GPT-5.5、Grok-4.5和GLM-5.2）的评估表明，逆向工程在很大程度上仍未得到解决：最强的模型GPT-5.6-sol每实例得分为61.4%，并且仅完全解决了31.5%的实例。我们的分析进一步表明，智能体的行为与人类工程师不同，智能体对编译器优化和静态链接相对不敏感。受控消融实验也证实了污染控制和真实规模都是必不可少的。这些结果表明，强大的源代码安全能力尚未迁移到二进制分析，凸显了逆向工程作为智能体网络安全的重要前沿，以及SRE-Bench作为衡量进展的严格测试平台。

## Abstract
AI agents are rapidly improving in cybersecurity capabilities when the source code is available for analysis, yet much of the software most consequential to cybersecurity, including malware, firmware, and proprietary applications, is available only as binaries. Analyzing such software requires reverse engineering(RE): recovering program semantics before the analysis can be meaningfully performed. However, evaluating agentic RE poses a fundamental challenge: benchmark instances must be unseen as source code in the LLMs' training data to prevent models from taking shortcuts by recognizing them rather than really analyzing them, while also matching the scale and anti-analysis protections of real software. Unfortunately, however, existing benchmarks do not jointly satisfy these requirements. To this end, we introduce SRE-Bench, the first realistic, contamination-free RE benchmark. Built entirely from scratch by RE experts with over 5,000 hours, SRE-Bench comprises 19 private, real-world-scale programs averaging 16.9K lines of code. We further developed 44 in-house anti-analysis primitives, yielding 262 binary instances and 1572 deterministically graded tasks. Our evaluation across five frontier LLMs (GPT-5.6-sol,Claude-Opus-5,GPT-5.5,Grok-4.5, and GLM-5.2) shows that RE remains largely unsolved: the strongest model, GPT-5.6-sol, scores 61.4% per instance, and fully solves only 31.5% of the instances. Our analysis further reveals that agents behave differently from human engineers, where agents are relatively insensitive to compiler optimization and static linking. Controlled ablations also confirm that both contamination control and realistic scale are essential. These results indicate that strong source-code security capabilities do not yet transfer to binary analysis, highlighting RE as an important frontier for agentic cybersecurity and SRE-Bench as a rigorous testbed to measure progress.

# 论文总结

## 1. 核心问题与整体含义

- **研究背景**：AI 智能体在源代码可获取的网络安全任务上能力快速提升，但现实中大量高价值目标（恶意软件、固件、专有软件）仅以二进制形式分发。据论文引用，46.5% 的在野漏洞来自不公开源代码的厂商，48% 的 2025 年零日漏洞针对专有企业软件，每天约有 73.2 万个新恶意样本出现。
- **核心问题**：二进制分析必须依赖逆向工程（RE），而评估智能体的 RE 能力存在根本性挑战：
  - **污染控制**：基准实例若源自公开源代码，模型可能在预训练中见过，从而通过识别而非真正分析来“作弊”；即便只是粗粒度的程序身份泄露也会破坏 RE 评估。
  - **真实规模与保护**：真实 RE 目标通常包含数千行代码，并带有复杂反分析保护层（如混淆、加壳），而现有基准普遍是 CTF 玩具题或小型程序，无法反映真实难度。
- **整体含义**：当前缺乏同时满足“无污染”和“真实规模/保护”的 RE 基准，导致无法准确衡量智能体在二进制层面的安全能力，也无法判断源代码安全能力是否能迁移到二进制分析。

## 2. 方法论

- **总体思路**：完全由 RE 专家从零开始、基于私有设计规范构建基准，确保任何程序、基础设施、保护层均不来自公开项目；同时开发多领域、多语言、真实规模的目标程序，并配套一套自研反分析保护套件。
- **基准构建**：
  - **19 个私有程序**，覆盖 5 个代表领域：网络协议、游戏、文件格式、恶意软件、固件。
  - **4 种实现语言**：C、C++、Rust、Go，遵循各语言惯用模式，使用不同库栈。
  - 平均每个程序 **16,915.8 行代码**，总代码量超过 320K 行（含基础设施），无任何两个程序共享源码。
  - 每个实例定义 **6 个确定性评分任务**，由专用 grading server / verifier / emulator 等基础设施自动评分。
- **保护套件**：
  - 44 个反分析原语，组织为 9 个技术族：混淆与字符串欺骗、按页认证加密、惰性解密与驻留最小化、测量密钥反调试、自校验与反篡改、在线许可与密钥交付、装载器逻辑虚拟化、反转储检测与欺骗、反重托管。
  - 套件由约 **27K 行 Python/C/汇编**从零编写，超过一半原语无公开实现。
  - 核心设计原则：**“折叠而非分支”**——将检测信号直接融入密钥派生，而非显式 if 判断，使绕过和观测失败表现为无信息的错误密钥。
  - 生成 8 种保护预设，结合 8 种未保护构建变体（优化、去符号、静态/动态链接），最终产生 **262 个二进制实例、1,572 个任务**。
- **评估流程**：
  - 智能体在隔离容器中运行，工具仅限 bash，配备标准 RE 工具（Ghidra、radare2、GDB、angr、binutils、strace、ltrace 等）。
  - 每实例 6 个任务，评分确定性、无反馈、无参考解泄露；参考解仅用于开发阶段证明可解性。
  - 进行**对抗性奖励黑客审计**：用智能体攻击开发中实例，发现捷径后修补，例如移除二进制中泄露的隐藏行为字符串。

## 3. 实验设计

- **评估对象**：5 个前沿 LLM：GPT-5.6-sol、Claude-Opus-5、GPT-5.5、Grok-4.5、GLM-5.2，均使用最高推理强度设置。
- **评估场景**：全部 262 个实例，每个实例在独立容器中运行，模型通过 API 调用与 bash 工具交互，最多 500 模型步、6 小时墙钟时间。
- **主要指标**：
  - **Score**：每实例 6 个任务的平均得分（0–6）；
  - **Solved**：完全恢复（6/6）的实例数；
  - **Zero**：零得分实例数；
  - 以及每实例 API 调用次数、成本、沙盒耗时。
- **对比设计**：
  - **模型横向对比**：同一基准上 5 个模型的能力排序。
  - **构建因素消融**：固定程序，分别改变优化级别、符号剥离、静态/动态链接、是否加保护，观察得分变化。
  - **污染与规模消融**：在同一任务（压缩文件格式恢复）上比较三个程序——约 1.1k LoC 的私有玩具程序、公开 gzip 的变体（修改约 200 行关键路径）、以及真实规模的私有 RevCompress——用两个模型在相同 8 个构建配置下测试。
  - **保护预设分析**：固定构建为优化+去符号+静态链接，比较 8 个保护预设下的得分。
  - **领域与语言分析**：按源语言（C/C++/Rust/Go）和目标领域（协议/格式/游戏/恶意软件/固件）分解得分。

## 4. 资源与算力

## 5. 实验数量与充分性

- **主要实验规模**：5 个模型 × 262 实例 = 理论上 1,310 次运行；实际产生可评分结果 1,252 次（Grok-4.5 有 44 次因超上下文未完成，若干次因安全拒绝）。
- **补充实验**：
  - 构建因素消融：4 个因素（优化、去符号、静态链接、保护）的得分分解；
  - 污染/规模消融：3 个程序 × 8 个构建配置 × 2 个模型 ≈ 48 次运行；
  - 保护预设分析：8 个预设 × 5 个模型；
  - 领域/语言分解：5 个领域、4 种语言。
- **充分性与客观性评价**：
  - 实验覆盖了基准全部实例，且包含多个受控消融，量化了设计选择的影响，客观性较好。
  - 统一容器、统一工具、确定性评分、随机秘密防止硬编码和重放、开发期奖励黑客审计等措施增强了公平性。
  - **主要不足**：基准仅有 19 个程序，其中固件域仅 3 个程序、6 个实例，统计置信度有限；模型仅 5 个，且均为闭源商业 API，无法完全排除版本更新或污染差异；分数分布呈两极（Solved/Zero），均值可能掩盖中间表现；API 成本导致难以多次重复运行以评估方差。

## 6. 主要结论与发现

- **RE 远未解决**：最强模型 GPT-5.6-sol 每实例平均仅 3.69/6（61.4%），完全解决仅 31.5% 的实例；最弱模型 GLM-5.2 平均 0.21，从未完全解决一个实例。模型间能力差距大（最强是最弱的 17 倍），表明基准具有良好的区分度。
- **智能体与人类 RE 行为不同**：
  - 优化和静态链接对智能体影响极小（GPT-5.6-sol 优化损失 0.08 分，静态链接损失 0.04 分）；
  - 符号剥离影响显著（GPT-5.5 从 2.53 降至 1.14），说明当前智能体更依赖符号名等“词汇锚点”，而非指令级推理。
  - 保护层是唯一同时困扰人类和智能体的经典障碍：保护使 GPT-5.6-sol 从 4.69 降至 2.50，其他模型几乎归零。
- **领域与语言差异**：领域差异远超语言差异；C 语言相对容易（工具链更成熟），Go/Rust 更难；恶意软件域最难（评分条件 conjunctive，要求同时移除恶意状态、保留良性状态、持久中和行为），协议和游戏相对容易。固件域得分异常高（样本少，需谨慎解读）。
- **污染与规模共同作用**：私有玩具程序（约 1.1k LoC）成本不足 $1.6、7 分钟即可被完全解决；公开 gzip 变体虽为真实程序，但因广泛出现在语料中，被两个模型在 10 分钟内、约 $2 内完全解决；只有同时具备私有性与真实规模的 RevCompress 才能区分模型（5.62 vs 3.75）。证明仅控制污染或仅保证规模都不够。
- **源代码安全能力尚未迁移到二进制分析**：高投入（更多 API 调用、更长耗时）并不必然带来更高分数，例如 GLM-5.2 花费更多却得分更低。

## 7. 优点

- **设计严谨**：从零构建、私有规范、不公开实例秘密、对抗性奖励黑客审计闭环，最大程度降低污染与捷径风险。
- **真实性与规模**：320K+ 行代码、平均 16.9K LoC 的程序，远超以往 RE 基准（30–470 倍），并配套 27K LoC 的自研保护套件，覆盖真实反分析技术。
- **可扩展性与确定性**：每个实例 6 个确定性评分任务，自动 grading server/verifier/emulator，移除评分代码和参考解，避免主观评分偏差。
- **多维度评估**：覆盖 5 个领域、4 种语言、8 个构建变体、8 个保护预设，并包含污染/规模消融和构建因素消融，提供了对能力来源的深入洞察。
- **发现具有指导意义**：揭示了智能体依赖符号名、对优化不敏感、保护层是主要瓶颈等与人类不同的失败模式，为未来 RE 智能体研究指明方向。
- **公平性措施**：每会话新鲜密钥/随机秘密防止重放和硬编码；隔离容器、统一工具、统一 API 设置、无评分反馈，保证模型间比较公平。

## 8. 不足与局限

- **基准规模有限**：仅 19 个程序，尤其固件域只有 3 个程序、6 个实例，导致部分领域结论（如固件最高分）统计效力不足。
- **模型覆盖与外部效度**：仅评估 5 个闭源商业模型，未包含开源模型；API 版本非固定，结果可能随时间漂移；无法控制模型内在的预训练污染差异。
- **保护套件为 alpha 阶段**：作者明确承认其并非不可破解，且可能无法完全代表商业混淆器；且保护仅适用于 Linux x86-64 静态可执行文件，固件域不适用于该套件。
- **任务结构与评分偏差**：每实例仅 6 个任务，且多数分数呈两极（Solved/Zero），可能掩盖中间能力；恶意软件域的 conjunctive 评分过于严格，导致弱模型全军覆没。
- **成本与可重复性**：总成本 $31.4K、1,812 沙盒小时，使得大多数研究团队难以完全复现；且仅有单次运行，未报告多次运行的方差。
- **领域偏向**：基准强调 Linux ELF、终端游戏、自研协议等，未覆盖 Windows PE、移动平台、嵌入式多架构等更广泛 RE 生态；语言上的 Go/Rust 难度可能受工具链成熟度影响而非模型真实能力。
- **工具包固定**：智能体仅配备一组预装 RE 工具，可能限制某些模型利用自身擅长工具的能力；API 调用步数限制也可能导致长任务被迫终止。
- **无反事实对照**：未与人工 RE 专家同基准定量比较，无法校准绝对难度水平。
