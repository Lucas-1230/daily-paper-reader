## 摘要
现实世界的网络攻击通常需要在多个主机和网络段间持续突破，使得多跳网络靶场成为研究和改进大语言模型智能体持续完成完整攻击链能力的关键基础设施。此前的工作已扩展了孤立的漏洞任务，并通过手动指定的漏洞语义构建了多主机场景，但仍无法将日益丰富的漏洞环境自动编排为端到端验证的多跳靶场。为此，我们提出RangeFactory，一个自动化的网络靶场编排框架，能够从孤立的漏洞环境大规模构建多跳网络靶场。RangeFactory将靶场构建建模为依赖关系解析：它从智能体对真实漏洞的实际攻击中提取依赖信息，通过模板引导的编排解析已知依赖，并利用端到端攻击执行来验证组合后涌现的运行时依赖。基于RangeFactory，我们构建了包含1,148个经验证靶场实例、覆盖287条不同攻击链的RangeBench，并从攻击深度、网络规模和任务信息等维度评估了前沿攻击智能体。在攻陷入口漏洞的运行中，仍有24.5%–47.0%未能完成后续攻击路径，揭示了初始据点建立与多跳攻击完成之间显著的持续攻击能力差距。RangeFactory还生成了一个含5,541条结果标注的多跳攻击轨迹语料库，为攻击过程分析和未来智能体训练提供了执行数据。

## Abstract
Real-world cyberattacks often require sustained progress across multiple hosts and network segments, making multi-hop cyber ranges essential infrastructure for studying and improving LLM agents' ability to sustain complete attack chains. Prior work has scaled isolated vulnerability tasks and constructed multi-host scenarios from manually specified vulnerability semantics. However, they are still unable to automatically orchestrate the growing supply of vulnerability environments into end-to-end validated multi-hop ranges. To this end, we present RangeFactory, an automated cyber-range orchestration framework that constructs multi-hop cyber ranges at scale from isolated vulnerability environments. RangeFactory formulates range construction as dependency resolution: it extracts dependency information from agents' actual attacks against real vulnerabilities, resolves known dependencies through template-guided orchestration, and uses end-to-end attack execution to validate runtime dependencies that emerge after composition. Using RangeFactory, we construct RangeBench with 1,148 validated range instances spanning 287 distinct attack chains and evaluate frontier attack agents across attack depth, network scale, and task information. Among runs that compromise the entry vulnerability, 24.5-47.0% still fail to complete the remaining attack path, revealing a substantial sustained-compromise gap between establishing an initial foothold and completing a multi-hop attack. RangeFactory further produces a corpus of 5,541 outcome-annotated multi-hop attack trajectories, providing execution data for attack-process analysis and future agent training.

## 2. 论文提出的方法论
### 核心思想
- 将多跳靶场构建分解为**依赖信息提取、依赖解析编排、端到端验证**三个阶段。
- 依赖关系分为两类：
  - **能力依赖**：前一漏洞利用后提供的能力（如命令执行、文件读取、网络可达性）是否满足下一漏洞利用的前置条件。
  - **运行时依赖**：攻击程序在新落脚点（中转主机）上能否实际运行，例如网络策略是否阻断反向连接、目标主机是否缺少所需工具。

### 关键技术细节
- **CVE能力原子**：每个成功利用的漏洞环境被封装为原子，包含：
  - `exploit_access`（利用所需条件）
  - `capability_grants`（利用后验证获得的能力）
  - `exploit_guide`（攻击复现步骤与运行时要求）
  - `poc_materials`（所需攻击材料）
  - 能力采用固定本体，如 `execute_command`、`read_file`、`network_vantage` 等，仅经过探测验证的授权参与编排决策。
- **三阶段多智能体流程**：
  1. **原子化**：利用“攻击者”代理在单漏洞环境中完成攻击，记录攻击程序与所需条件；随后“探索者”代理基于已得能力进行探测，确认并记录可用的后续能力，共同形成能力原子。
  2. **编排**：**生成器**根据公开架构参照生成参数化企业网络模板，定义网络分层与攻击链骨架；**编曲器**按攻击顺序，基于能力接口和模板通信策略进行依赖匹配与可行性剪枝，仅保留满足能力过渡和已知运行时约束的绑定组合，生成候选靶场。
  3. **验证**：部署候选靶场，由**执行器**代理复用各原子的攻击构件，在复合环境中执行端到端攻击；私有验证器独立检查每个节点的隐藏目标是否被达成。成功则接受实例，失败则由**诊断器**区分攻击执行失败（允许限次重试）与绑定冲突（将不可行条件存入记忆，供后续编排使用）。
- 核心过程采用算法 `Dependency-Constrained Composition` 进行深度优先的槽位展开，并在每一步根据累积状态判断原子兼容性；验证算法采用分层验证，先进行确定性环境检查，再执行引导式攻击，只有通过所有验证的靶场才被保留。

## 3. 实验设计
- **数据集/场景来源**：从 Vulhub 和 CVE-Factory 中筛选出 257 个可部署且可利用的网络服务漏洞环境，最终成功转换为 239 个能力原子，覆盖 122 种产品和 2010–2026 年的 CVE。
- **靶场模板**：基于公开架构参照生成 5 种三层企业网络模板（DMZ → 应用内网 → 数据网），并配有 4 种规模（约7、12、31、50个可见节点），共 20 种配置。
- **Benchmark 构建**：利用 RangeFactory 产生 1840 个候选靶场，经端到端验证得到 1148 个实例，构成 **RangeBench**，涵盖 287 条不同的有序攻击链，每条链均部署在 4 种匹配的网络规模上下文中。
- **对比方法/代理**：在 RangeBench 上评估了 4 个前沿 LLM 攻击智能体：`Kimi-K3`、`GLM-5.2`、`DeepSeek-V4-Pro`、`GPT-5.6-Luna`。评测维度包括：
  - **攻击深度**（1跳、2跳、3跳成功率的递减）
  - **任务信息水平**（L0：仅知入口和最终目标；L1：增加网络拓扑；L2：进一步增加目标服务、CVE映射及凭据）
  - **网络规模**（对比同一条攻击链在 4 种背景资产规模下的表现）
- **消融对比**：对比了四种组合策略（随机绑定、基于元数据匹配、能力匹配、全编排）对候选有效性的影响，并分析了诊断器与端到端验证的作用。
- **轨迹收集**：共收集 5541 条结果标注的多跳攻击轨迹，包含引导辅助的演示轨迹和 Kimi-K3 在 L0/L1/L2 下的自主探索轨迹。

## 6. 论文的主要结论与发现
- **可扩展构建能力**：RangeFactory 成功从 239 个孤立的 CVE 环境大规模构建出 1,148 个端到端验证的多跳靶场，验证成功率达 62.4%，自动化程度高，无需人工逐范围绑定或标注。
- **显著的持续攻击差距**：在所有成功攻陷入口漏洞的运行中，仍有 24.5%–47.0% 的 LLM 代理未能完成后续攻击步骤；攻击深度每增加一层，成功率显著下降，证明“夺得一跳”远不代表能完成多跳攻击。
- **任务信息的影响**：为代理提供更多信息（L2 级别包含 CVE 映射与凭据）能大幅提升成功率（从 15.4% 升至 55.7%，以 Kimi-K3 为例），但最好的模型仍有近一半失败，说明信息丰富并不能消除持续执行的难度。
- **网络规模效应**：扩大靶场背景资产规模会显著增加代理的交互成本（工具调用次数和耗时上升 51%–84%），但对最终攻击成功率的负面影响相对温和（降幅约 10 个百分点）。
- **编排与验证的互补性**：依赖引导的编排能筛掉大量不可行组合，但单纯部署检查无法替代端到端攻击验证，诊断反馈则有助于恢复部分攻击并积累排斥性知识。

## 7. 优点
- **问题建模创新**：将多跳靶场构建建模为依赖解析，并同时考虑能力依赖与运行时依赖，设计清晰、可操作。
- **高度自动化与规模化**：通过“攻击获取依赖 → 模板化组合 → 端到端验证”的闭环，真正实现了从单漏洞环境到多跳靶场的无人流动构建，显著降低了人工开销。
- **信息隔离与公平评估**：构建时所用的攻击导引和验证状态对评估代理完全隐藏，并设计了 L0–L2 的信息梯度，能够区分信息丰富度与代理能力的效应。
- **贡献维度丰富**：不仅提供了可复现的靶场基准 RangeBench，还产出了大规模标注攻击轨迹数据集，为攻击过程分析和未来训练开源了数据基础。
- **机制设计精细**：能力原子的验证级（`verified` vs `inferred`）、模板参数化、诊断器的双路反馈（重试与排斥记录）等一系列机制，增强了系统的可靠性与效率。

## 8. 不足与局限
- **场景覆盖范围受限**：
  - 所有靶场均为 **三层线性攻击链** 且基于 **容器化企业网络**，不包含 Windows 域、云 IAM、分支或合并式攻击图等更复杂或真实的攻击路径。
  - 攻击链仅限于网络服务漏洞的线性串联，未涉及社工、物理接触或供应链攻击等。
- **验证器偏差风险**：所有保留的靶场均以 DeepSeek-V4-Pro 作为引导式执行器成功通过为前提，可能引入 **构造工具依赖的偏差**，误拒某些其他模型可能成功的路径；经重验，约 8% 的拒绝实例可被另一模型恢复，说明接受集并非完备。
- **统计局限性**：基准评测采用每个实例单次 rollout，无法估计模型在任务内的随机变异；论文虽提供了保守的组级置信区间，但仍承认模型间的差距在极有限样本下可能不显著。
- **安全与伦理边界**：所有实验在隔离授权环境中进行，使用公开的 CVE，但完整的攻击构件和轨迹在发布中经安全审查与脱敏，原始 PoC 可能被限制公开，这在一定程度上限制了直接复现性。
- **未涉及防御与检测**：RangeBench 仅关注攻击端的执行成功率，未在靶场中集成任何入侵检测、流量监控或防御机制，尚不能评估代理在存在对抗防御时的攻击隐蔽性或鲁棒性。
