## 摘要
夺旗（CTF）基准被广泛用于评估自主语言模型智能体的攻击性安全能力。现有评估依赖浅层的二元判断或汇总分数，忽视了智能体获取 Flag 的轨迹。因此，实际的漏洞利用与 Flag 直接暴露、记忆性召回、外部查找、猜测以及缺乏依据的声明被混为一谈，可能高估智能体的网络安全能力。我们提出 CTF-ABACUS，一个基于轨迹的智能体审计框架，将每次运行重建为以证据为依据的解题画像。该框架将智能体动作分解为渗透测试阶段和分类技术，识别漏洞利用发生的位置、Flag 首次出现的位置，以及恢复得到的 Flag 是否得到所展示行为的支持。跨智能体聚合解题画像可得到题目特征签名，揭示成功是通过预期漏洞利用还是通过捷径路径实现的。我们将 CTF-ABACUS 应用于六种前沿模型和开源模型在 240 道题目上的 1,435 次 CTF 尝试，在两种评判视角下得到 2,870 份解题画像。经轨迹验证的漏洞利用仅占各基准中恢复得到的 Flag 的 62%–87%，而捷径恢复对应的轨迹则明显更浅。这些发现将 CTF 评估从统计恢复得到的 Flag 转向验证所展示的漏洞利用，并为设计能更好隔离攻击性能力的基准提供了基础。

## Abstract
Capture-the-Flag (CTF) benchmarks are widely used to assess the offensive security capabilities of autonomous language-model agents. Evaluations rely on shallow binary judgments or aggregate scores, overlooking the agent's trajectory to the flag. Consequently actual exploitation is conflated with direct flag exposure, memorized recall, external lookup, guessing, and unsupported claims, potentially overstating the agent's cybersecurity capability. We introduce CTF-ABACUS, a trace-based agent auditing framework that reconstructs each run as an evidence-grounded solve profile. By decomposing agent actions into penetration-testing phases and categorical techniques, it identifies where exploitation occurs, where the flag first appears, and whether the recovered flag is supported by demonstrated behavior. Aggregating solve profiles across agents yields challenge signatures that reveal whether success was achieved via the intended exploit or via shortcut pathways. We apply CTF-ABACUS to 1,435 CTF attempts by six frontier and open-source models on 240 challenges, yielding 2,870 solve profiles under two judge lenses. Trace-verified exploits account for only 62-87% of recovered flags across benchmarks, while shortcut recoveries follow substantially shallower trajectories. These findings shift CTF evaluation from counting recovered flags to verifying demonstrated exploitation and provide a basis for designing benchmarks that better isolate the offensive capabilities.

  现有 CTF（Capture-the-Flag）基准广泛用于评估 LLM 智能体的攻击性安全能力，但评估通常只给出二元判定（是否提交了正确 flag）或汇总分数，完全不考察智能体获取 flag 的轨迹。

## 6. 主要结论与发现

- **Flag 恢复并不等于真实利用**  
  在全部恢复的 flag 中，仅 72.9% 有执行证据支持；10.9% 为人工验证的推理推导；16.2% 缺乏任何形式证据。不同基准下，trace-verified exploits 占比在 62%–87% 之间。

- **真实利用与捷径在轨迹上显著不同**
  - 真实利用：平均 PTES 深度 4.3，单调性 0.80，89% 到达 Exploitation 阶段。
  - 捷径恢复：平均深度 2.8，单调性 0.50，仅 42% 到达 Exploitation 阶段。
  - 技术使用上，真实利用更多使用 `author_solve_script`（35.7% vs 12.2%），捷径更多出现 `flag_submission`（1.8% vs 23.4%）。

- **基准质量差异明显**
  - CTFTiny 和 HTB 在真实利用占比、深度、单调性和 Exploitation 到达率上领先；
  - Cybench 恢复率最低且未支持占比最高（31.0%），说明难度与证据有效性是不同维度；
  - InterCode-CTF 恢复率高但轨迹浅。

- **验证评分会显著改变模型排名**
  - 要求执行证据后，各模型分数下降 17.4%–22.6%；
  - 汇总排名相关性降至 0.60，且调整主要取决于基准而非模型身份（基准解释方差约为随机期望的 17 倍，模型解释方差低于随机期望）。

- **挑战有效性是交互属性**
  - 即使计入人工验证的推理推导，仍有 33.2% 的挑战存在跨模型混合解决路径；
  - 同一终局分数可能代表完全不同的证据：例如 `robust_cbc` 直接暴露 flag，而 `rev-76` 均通过验证推导。

- **直接暴露远多于记忆污染**
  - 未支持恢复中，直接暴露 151 例，记忆 / 外部查找仅 17 例，相差 8.9 倍。

## 7. 优点

- **轨迹级溯源视角**：首次系统性地将 flag 来源与行为证据关联，区分“恢复 flag”和“证明利用”，弥补了传统评分的核心缺陷。
- **证据接地与可复现**：基于实际工具调用和观察输出，规则明确、流程版本化，标签依据公开标准（PTES、OWASP、CWE、CAPEC、MITRE ATT&CK、NIST）。
- **双裁判 + 人工复核**：使用不同家族 LLM 裁判并进行盲审评分，辅以安全专家人工复核，降低单一模型偏差。
- **挑战签名机制**：将单个运行聚合为题目级画像，为基准设计者提供诊断工具，识别哪些挑战无法有效测量目标能力。
- **大规模实证**：覆盖 1,435 次尝试、6 个模型、4 个基准、240 个挑战，并给出定量分解。
- **可解释性强**：通过 PTES 阶段、技术分布、单调性等可视化轨迹几何，行为差异直观且可量化。

## 8. 不足与局限

- **标注与判断仍依赖 LLM 和人工**  
  利用行为 \( \xi \) 的推断、阶段 / 技术标注仍主要由 LLM 完成；虽有人工复核，但仅覆盖 10% 样本和 reasoning-only 案例，存在未发现的误标风险。

- **挑战设计带来的模糊性**  
  在琐碎或环境可疑的挑战中，真实利用可能被误读为捷径，反之亦然；这种模糊性源于挑战本身而非审计方法，但仍会影响结论。

- **环境与配置单一**  
  所有运行均基于 D-CIPHER harness 的默认配置，未探索不同智能体框架、prompt 或工具配置下的稳健性。

- **外部有效性有限**  
  结论来自四个特定公开 CTF 基准，可能无法完全推广到实时竞赛、真实渗透测试或更开放的靶场环境。

- **未提供算力与成本明细**  
  缺少 GPU / API 成本统计，难以评估审计流程本身的计算开销与可扩展性。

- **个性化检测能力不足**  
  虽然群体层面行为模式清晰，但单个特征最高 AUC 仅 0.617，说明无法用简单规则可靠区分单次恢复是否真实，仍需完整的序列级重建。
