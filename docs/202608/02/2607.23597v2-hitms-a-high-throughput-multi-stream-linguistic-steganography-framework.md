## 摘要
生成式语言隐写将秘密比特隐藏在大型语言模型的采样随机性中。现有方案是单流的，通过单个对单个提示的响应传递整个秘密。这种惯例带来了一些局限：它没有为批量多流推理提供协议级别的支持，且朴素的协同批处理不会隐藏时隙占用或有效载荷完成情况。我们提出了高通量多流（HiTMS）框架，它将秘密分布在通过连续交互轮次联合产生的多个响应中。每一轮在单个批量调用中嵌入和提取多个流，从而分摊模型调用的成本，显著提高吞吐量。为确保可恢复性，HiTMS将每个响应封装在一个自描述帧中，并采用一个密钥派生的调度，将流绑定到时隙，并用诱饵填充未使用的时隙，保证精确恢复，同时隐藏活跃流的数量。该框架与语言模型和隐写编码器无关。在八个数据集-模型-编码器设置中，八流HiTMS的嵌入和提取速度比单流基线最高提高了4.3倍，同时将隐写分析器的平均接收者操作特征曲线下面积（AUROC）从0.681降低到0.601。使用4到64个流的实验表明，随着并发度的增加，吞吐量持续提升。本工作的GitHub仓库为https://github.com/ryehr/HiTMS_steganography。

## Abstract
Generative linguistic steganography conceals secret bits within the sampling randomness of large language models. Existing schemes are single-stream, conveying an entire secret through a single response to a single prompt. This convention incurs limitations: it provides no protocol-level support for batched multi-stream inference, and naive co-batching does not conceal slot occupancy or payload completion. We propose the High-Throughput Multi-Stream (HiTMS) framework, which distributes a secret across multiple responses produced jointly over successive rounds of interaction. Each round embeds and extracts several streams within a single batched call, thereby amortizing the cost of model invocation and substantially improving throughput. To ensure recoverability, HiTMS wraps each response in a self-describing frame and employs a key-derived schedule that binds streams to slots and fills unused slots with decoys, guaranteeing exact recovery while concealing the number of active streams. The framework is agnostic to both the language model and the steganographic coder. Across eight dataset-model-coder settings, eight-stream HiTMS achieves up to 4.3 times higher embedding and extraction speeds than single-stream baselines, while reducing the average area under the receiver operating characteristic curve (AUROC) of steganalyzers from 0.681 to 0.601. Experiments with 4 to 64 streams demonstrate sustained throughput gains as concurrency increases. GitHub repository for this work is https://github.com/ryehr/HiTMS_steganography.

### 1. 研究动机与核心问题
- **核心问题**：现有的生成式语言隐写术都是“单流”的，即一次秘密对话只能通过一个模型响应传递，无法利用大语言模型（LLM）的批量推理能力来同时处理多个秘密。这导致两个关键问题：
  - 协议层面缺乏对批量多流推理的支持，无法高效并发传输。
  - 朴素的共批处理（co-batching）会泄露批次大小变化、响应长度等信道占用信息，从而被隐写分析器检测。
- **研究目标**：提出一个与模型和编码器无关的高通量多流语言隐写框架，能够在多轮交互中，通过一次批量模型调用同时嵌入多条秘密消息，并保证精确恢复和隐蔽性。

### 2. 方法论
- **核心思想**：将多条独立秘密消息（流）分段，分配到多轮批量推理生成的多个响应中，通过单次批量模型调用完成多流的嵌入与提取，从而分摊计算开销，大幅提升吞吐量。
- **关键技术细节**：
  - **多流调度**：使用密钥派生的伪随机函数（PRF）在每一轮决定哪些活跃流被服务，并将其映射到具体的响应槽位（slot）。未使用的槽位用从密钥派生的“诱饵”比特流填充，使得外部观察者无法区分活跃流与诱饵。
  - **自描述帧结构**：每个活跃槽位的响应携带一个加密的长度头（header），指示该流剩余未发送的比特数，后面跟着加密的负载和填充比特。接收方通过解密头信息即可知道从响应体中提取多少比特属于真正的负载，其余为填充，从而保证即使响应长度动态变化也能精确恢复。
  - **加密与认证**：负载位与流特定的密钥流异或加密，头信息也与PRF异或，保证消息机密性和伪随机性，使活跃流、诱饵流在比特级不可区分。
  - **批量嵌入与提取**：发送方和接收方均在每一轮调用一次批量嵌入（Batch Embed）或批量提取（Batch Extract），在语言模型自回归生成时并行处理所有槽位，每一步从模型分布中根据隐写编码器（如算术编码、Discop）嵌入或提取秘密比特。
  - **数学描述**：核心公式定义了流到槽的映射、头加密、负载加密、以及嵌入/提取接口。整体流程在算法1—4中详细给出，保证了往返同步和有限步内终止。
- **安全性设计**：通过密码学假设和混合论证证明了方案的隐写不可感知性、流模式隐蔽性和消息机密性。

### 6. 主要结论与发现
- **吞吐量大幅提升**：在8种数据集–模型–编码器组合下，8流HiTMS的嵌入速度比基本单流平均快 **3.2倍**（最高4.3倍），提取速度也成比例提升。这一增益来自于将一次模型调用分摊到多个流上。
- **安全性改善**：HiTMS平均将隐写分析器AUROC从0.681降低到0.601，尤其在Llama模型上显著降低了被检测概率。其填料设计缓解了因提前截断导致响应长度异常的漏洞，是安全性提升的部分原因。
- **可扩展性验证**：在4~64流范围内，吞吐量随并发流数增加而持续增长，但增速低于线性，原因是CPU上的编码开销和最后完成的“长尾流”效应。
- **通用性**：HiTMS不改变底层编码器, 可与算术编码、Discop等配合工作，且对语言模型无特殊要求。

### 7. 优点
- **实际意义强**：首次在生成式语言隐写中引入多流批量推理协议，显著提高了秘密传输效率，为后续语言隐写即服务（LSaaS）奠定基础。
- **完善的自描述帧设计**：通过加密头、负载加密切片、诱饵流和填充机制，在不等长响应和多轮中仍能保证精确恢复，并隐藏了活跃流数量、负载边界等侧信道信息。
- **理论分析与实证结合**：给出了安全性定理（隐写不可感知性和流模式隐私）和详细的实验评估，代码开源。
- **兼容性好**：与模型和编码器解耦，可即插即用。

### 8. 不足与局限
- **编码开销**：随着批量增大，CPU端的隐写编码计算成为瓶颈，限制了大规模批量下的线性加速比。
- **尾延迟效应**：多流方案受最慢完成的流拖累，导致吞吐量的实际增长略低于理论值。
- **评估环境限制**：仅在两个模型、两个数据集上测试，未覆盖更大模型或更长对话场景；LLM法官评分可能存在偏差，且未进行人类评估。
- **安全性假设**：安全性基于密码原语的可证明安全，但现实中活字模型分布偏移、微调影响等未做深入分析。
- **未涉及抗信道噪声**：实验在无噪声的理想传输条件下进行，未考虑实际网络传输中可能的文本篡改或丢失。
