## 摘要
渗透测试至关重要但资源密集。尽管大语言模型（LLM）在自动化安全审计方面显示出前景，现有智能体主要是在简化的线性场景中执行端到端工作流。现实世界的黑盒测试本质上是非线性的：攻击图最初未知，必须根据环境反馈逐步推断。观察结果可能揭示多个攻击分支，失败往往含义模糊，关键线索可能跨越较长的行动跨度。因此，现有智能体往往陷入深度优先探索、误判失败原因并遗忘先前证据。我们提出 MazeRunner，一个基于三智能体任务与线索编排框架的自主渗透测试系统。它将全局编排、上下文密集型执行和面向失败的审查分离开来，同时持续维护任务状态和环境证据。这一设计支持行动修正、前提恢复、分支切换和长距离线索关联。我们在 10 个近期发布的 HTB 目标上评估 MazeRunner，将每次系统-目标运行限制为 2000 万个 LLM token，并防止特定目标解题信息泄露。使用 Claude Sonnet 4.5 时，MazeRunner 完成了 47.7% 的标注子任务，而 PentestGPT-V2 为 36.2%，Claude Code 为 34.2%。它在六个目标上获得用户级或更高权限，其中在两个目标上获得 root 权限；每个同模型基线仅在两个目标上达到用户级权限，且从未获得 root 权限。执行轨迹分析进一步表明，MazeRunner 探索了更多攻击分支，并更高效地获取 shell。

## Abstract
Penetration testing is essential yet resource-intensive. Although large language models (LLMs) show promise for automating security auditing, existing agents mainly execute end-to-end workflows in simplified linear scenarios. Real-world black-box testing is fundamentally nonlinear: the attack graph is initially unknown and must be incrementally inferred from environmental feedback. Observations may reveal multiple attack branches, failures are often ambiguous, and critical clues may span long action horizons. Existing agents therefore tend to become trapped in depth-first exploration, misdiagnose failures, and forget prior evidence. We present MazeRunner, an autonomous penetration testing system built on a three-agent task-and-clue orchestration framework. It separates global orchestration, context-intensive execution, and failure-oriented review while persistently maintaining task states and environmental evidence. This design supports action revision, prerequisite recovery, branch switching, and long-range clue correlation. We evaluate MazeRunner on 10 recently released HTB targets, limiting each system-target run to 20 million LLM tokens and preventing target-specific solution leakage. With Claude Sonnet 4.5, MazeRunner completes 47.7% of annotated subtasks, compared with 36.2% for PentestGPT-V2 and 34.2% for Claude Code. It achieves user-level or higher access on six targets, including root access on two; each same-model baseline reaches user-level access on only two targets and never obtains root access. Execution-trace analysis further shows that MazeRunner explores more attack branches and acquires shells more efficiently.

- 论文研究的是**基于大语言模型（LLM）的黑盒自动化渗透测试**。

- 现有 LLM 代理因此容易出现三大瓶颈：

  - **上下文遗忘**：有限上下文窗口导致早期线索被覆盖或遗忘；
  - **错误归因**：失败后错误地将原因归到不相关任务，过早放弃可行攻击路径。
- 论文提出 MazeRunner，意在通过**任务与线索的非线性编排**，让自主渗透测试系统能够在复杂黑盒环境中实现分支切换、失败恢复与长程证据复用。

## 2. 方法论

### 2.1 核心架构：三代理协作循环

MazeRunner 由三个专职代理组成闭环：

- **Strategist（策略代理）**：
  - 负责全局攻击任务编排；
  - 将高层目标分解为可调度的任务；
  - 根据执行反馈和 Reviewer 建议动态修订任务图、补充前提任务、切换分支。
- **Executor（执行代理）**：
  - 负责将任务转换为具体 CLI 命令或远程交互；
  - 使用 Nmap、Gobuster、ffuf、curl、ssh、Metasploit 等标准工具；
  - 支持**非交互式执行**（扫描、枚举等）和**基于 PTY 的交互式执行**（维持 shell 会话、处理认证提示、稳定反向 shell）。
- **Reviewer（审查代理）**：
  - 不直接调度任务，而是分析失败执行轨迹；
  - 判断失败原因属于：
    1. 高层攻击路径错误；
    2. 局部执行问题（工具、命令、交互）；
    3. 前提条件未满足；
  - 同时从失败输出中提取新线索，如用户名、路径、配置片段、服务版本等。
  - 为 Strategist 提供可操作的修正建议。

### 2.2 任务与线索缓存

- 使用 **Task Graph**（任务图）维护攻击拓扑：
  - 每个任务具有唯一 ID、描述、依赖边、状态、执行记录；
  - 状态包括 `pending`、`ready`、`running`、`completed`、`failed`、`blocked`；
  - 依赖满足后由程序化逻辑自动从 `pending` 转为 `ready`，不消耗 LLM 推理。
- 使用 **Clue Graph**（线索图）维护环境证据：
  - 记录开放端口、服务指纹、凭据、配置片段、错误日志等；
  - 显式关联“生产者任务”和“潜在消费者任务”，支持跨阶段推理。
- 这种设计使得系统能够：
  - 回溯到有效上游节点；
  - 在一个分支死亡后激活其他依赖已满足的分支；
  - 跨长执行跨度复用早期发现的线索。

### 2.3 工作流过程

1. 用户给出高层目标，例如“获取目标主机的 root shell”；
2. Strategist 构建初始任务集合；
3. Executor 执行 `ready` 状态任务，收集 stdout、stderr、退出码、会话状态和新线索；
4. Reviewer 对失败或不确定任务进行诊断；
5. Strategist 基于状态、依赖、Reviewer 建议和新线索重新规划：
   - 修正后可重试失败任务；
   - 创建新的前提任务；
   - 剪枝死分支并切换其他攻击路径；
6. 循环执行，直到达到目标、预算耗尽或无可执行任务。

论文还给出了三种典型运行模式：
- **本地任务调整**：修正加密算法等局部参数；
- **前提识别与补充**：发现缺少 vhost，增加 vhost 发现任务；
- **分支切换**：失败后根据缓存线索切换到哈希破解等其他分支。

## 6. 主要结论与发现

- 在 Claude Sonnet 4.5 下：
  - MazeRunner 子任务完成率为 **47.65%**；
  - PentestGPT-V2 为 **36.24%**；

- DeepSeek-V3.2 下也观察到一致优势：
  - MazeRunner 完成率 39.60%，优于同模型两个基线。
- 探索广度：
  - MazeRunner 的中位探索广度最高；
  - Claude Code 平均探索广度较低，倾向于过早终止；

- 失败原因分析：
  - MazeRunner 显著降低了 Planning Error 和 Clue Forgetting；
  - 其失败更多集中在 Code/Payload Failure，说明系统已推进到执行密集阶段；

  - 去除 Task & Clue Cache：完成率从 73.5% 降至 58.8%，token 开销增加 27.7%；

  - 证明 Reviewer 和 Cache 对避免深度优先陷阱和上下文遗忘至关重要。

## 8. 不足与局限

- **破坏性操作仍需人工审查**：在真实业务环境中，部分操作需专家确认，尚且不能完全零干预；
- **LLM 统计偏差**：面对多个攻击路径时，模型倾向优先尝试常见漏洞，罕见攻击向量可能被忽略；

- **手动干预**：如密码爆破环节采用人工操作，影响严格意义上的端到端自动化评估；
- **未见与更多最新前沿代理模型的完整对比**，仅在讨论中提及 Kimi K3 等可能的互补关系。
